# Gateway glossary

Use this alongside [How a request crosses AI Gateway](gateway-architecture.md).
Aliases below explain how a term appears in conversation and code. Directional
terms use the Gateway server's point of view unless stated otherwise.

## Components and direction

| Term and aliases | Meaning and why it matters | Code or further reading |
| --- | --- | --- |
| Client; caller; consumer | The application making a request. A browser, application server, and Gateway's outbound HTTP client occupy different positions; always identify which hop is meant. Gateway credentials belong on the application server. | [Go client](../providers/grafana-gateway.md) |
| Adapter | Converts between representations. An **inbound** adapter accepts a client protocol; an **outbound** adapter turns common model calls into a native provider protocol. Supporting one direction does not establish support for the other. For the per-attempt option hook, see translator. | [Component diagram](gateway-architecture.md#the-pieces-and-their-boundaries) |
| Provider; model provider; provider adapter | Can mean the remote vendor, its Go adapter package, or a configured account instance. `provider.LanguageModel` is the common model interface. A public model name is not necessarily a native model ID. | [Providers and models](providers.md) |
| Native; upstream | The provider's own API, payloads, or metadata, beyond Gateway's common representation. In parity discussions, **upstream** instead means the pinned Vercel source; it does not mean the live model service. | [Parity baseline](../../test/conformance/upstream.yaml) |
| Ingress; inbound; frontend API | The boundary receiving client traffic. Here, “frontend” can mean the server's public API, not a browser UI. The plugin backend exposes ProviderWire ingress. | [Routes](../../ai-gateway/pkg/internal/gateway/routes.go) |
| Egress; outbound | Traffic from Gateway to a provider or other dependency. An inbound authenticated request does not by itself establish safe outbound network access. | [Gateway plugin](../../ai-gateway/README.md) |
| ProviderWire; ProviderWire V4 | HTTP representation of model calls and provider results, consumed by Gateway clients. It carries JSON for unary results and provider events over SSE for streams. It is distinct from the UI message protocol consumed by React hooks. The Gateway serves it as a codec over the shared execution runtime. | [ProviderWire handler](../../ai-gateway/providerwire/v4/handler.go) |
| Execution runtime; runtime; `execution.Runtime` | Selects and invokes the model for every Gateway API adapter, rebuilds the prompt's tool history, validates the output lifecycle, classifies failures into closed categories, captures fallback attempts, and owns stream waits, idle time, drain and how a stream ends. It never writes HTTP responses; each API adapter, such as ProviderWire, owns mapping, representation, encoding, framing, its error documents and its own protocol state machine. | [Execution package](../../ai-gateway/internal/execution/doc.go) |
| Output lifecycle validation; lifecycle rules; invalid output; `ErrInvalidOutput` | The runtime's checks that provider output is well formed as a sequence, seeded from the pending provider-executed calls in the prompt's tool history: stream-start position, response segments, text and reasoning IDs, tool input, call, preview, result and approval phases, and finish preconditions, plus the unary equivalents. A violation is **invalid output**: classified as internal, with the attempt view of a successful call, because the provider call succeeded and the Gateway refused its output. Adapters keep their representation and content checks, such as UTF-8, and their own protocol state machine, but no provider output lifecycle rule. | [Stream validator](../../ai-gateway/internal/execution/stream_validation.go) |
| Host contract; adapter contract | What the Gateway host provides to every API adapter (access decision, telemetry, selection, discovery listing and per-attempt option translation) and what each adapter supplies (its handler over the execution runtime, a host-error writer for the closed host-error categories, and an optional discovery projection). | [Host package](../../ai-gateway/internal/host/doc.go) |
| Translator; option translator; per-attempt translation | A function an inbound adapter supplies with a call to map its API semantics to one candidate's native options. The host applies it to each physical attempt, inside fallback and outside native option validation, so each candidate in a mixed Anthropic and OpenAI chain sees only its own translation. Host policy re-checks the result. | [Translation](../../ai-gateway/internal/execution/translate.go) |
| Gateway composition; distribution; `gateway.Run` | The public, experimental (v0) entrypoint that runs the plugin backend. It owns the plugin runtime, plugin ID, authenticator, the app provider that receives the host's API access configuration, lifecycle events and the final flush, so a distribution cannot miss them. A **distribution** is a plugin backend whose `main` calls it; the shipped `pkg/main.go` is one. Its options are empty today. | [Composition package](../../ai-gateway/pkg/gateway/doc.go) |
| Route table; route entry | The list of `{method, path, label, handler, host-error writer}` entries the plugin backend serves. The production table must match the committed manifest; registering an adapter means adding one entry. Requests matching no entry do no work. | [Routes](../../ai-gateway/pkg/internal/gateway/routes.go) |
| Transport; HTTP client | Moves requests and responses across a hop. Provider translation sits above transport; a successful TCP/HTTP exchange need not be a successful model invocation. | [Native model composition](../../ai-gateway/pkg/internal/nativemodel) |
| Middleware; wrapper | Behavior surrounding another handler or model. HTTP middleware covers routing/authentication/HTTP observation; model middleware surrounds `DoGenerate` and `DoStream`. Their positions determine what failures they can see. | [Middleware overview](../middleware/overview.md) |

## Identity, selection, and control

| Term and aliases | Meaning and why it matters | Code or further reading |
| --- | --- | --- |
| Authentication; authn | Establishes who the caller is. The plugin host verifies a platform-delegated token against the platform signing keys; there is one verified-token path, not separate JWT/static-key or trusted-proxy paths. It precedes the access decision and ProviderWire decoding on protected routes. | [Authentication guide](../guides/gateway-authentication.md) |
| Authorization; authz; scope | Decides what an identity may do. A valid token alone does not imply access; `Decide` maps the token and route namespace to configured, BYOK, or refused access under the `access_mode`, `DecideCatalog` maps it to catalog or refused access on a catalog route, and the token namespace must cover the route namespace. | [Authentication guide](../guides/gateway-authentication.md) |
| Catalog route; catalog access; `aigateway:modelinvoker` | The `config` and `language-model` routes of one `ModelCatalog`, under `.../modelcatalogs/{name}/`, which clients use as their base URL. Grafana runs their declared `get` checks on the route subresources, which the `aigateway:modelinvoker` role (bound to Editor) grants, and passes the catalog and its decrypted keys to the plugin. Callers get catalog access, which selects and lists only that catalog. | [Catalog routes](../../ai-gateway/pkg/internal/gateway/catalog_route.go) |
| Catalog; discovery; public model inventory | Maps public names and aliases to configured model objects and describes available choices. Discovery lists public models; it is not a dump of credentials or all vendor models. | [Catalog guide](../../ai-gateway/docs/model-catalog.md) |
| Model catalog kind; `ModelCatalog`; stack catalog | A stack's catalog stored in Grafana as a `ModelCatalog` resource: providers, models, aliases and fallbacks, with one provider key per provider held as a Grafana secure value named after the provider. It is distinct from the operator catalog, which the Gateway reads at startup with keys from its environment. Its admission validator (Kubernetes admission, not capacity admission control) refuses invalid catalogs; the `aigateway:catalogreader` and `aigateway:catalogwriter` roles control who reads and writes them, and its catalog routes serve its models. | [Stack catalog checks](../../ai-gateway/pkg/internal/stackcatalog/doc.go) |
| Stack-catalog selection; `SelectStackCatalog` | Selection from one stored stack catalog for one request, with the catalog's decrypted keys: it re-checks the catalog, applies routing controls and fallbacks like the operator catalog, refuses BYOK controls, and constructs only the candidates its chain attempts. Its selection carries the catalog name and keys, so failure summaries redact them and telemetry names the catalog without making it a metric label. | [Stack-catalog selection](../../ai-gateway/pkg/internal/service/stack_catalog.go) |
| Catalog configuration error; `ErrCatalogConfiguration` | The failure category of a stored stack catalog that fails its checks or lacks a provider key. Its fixed 424 `failed_dependency` document never echoes catalog content or keys, because the caller's request is valid and only a catalog change can fix it. | [Classification](../../ai-gateway/internal/execution/classify.go) |
| Egress policy; egress client; `ErrEgressRefused` | The check on a stack catalog's custom endpoints: `https` only, and every address the egress client connects to after DNS resolution must be public unless `stack_catalog_egress_allow` lifts it and `stack_catalog_egress_deny` doesn't refuse it. The client uses no proxy and its own connections, so neither hides or reuses a destination. A refusal or failed resolution gets a fixed 424 `failed_dependency` document that names no host or address. Operator-catalog endpoints aren't checked. | [Egress client](../../ai-gateway/pkg/internal/outbound/egress_client.go) |
| Alias; canonical ID; native model ID | An alias resolves to a canonical public model such as `assistant`; that model's candidates carry native provider model IDs. Keeping these identities separate makes fallback understandable. | [Catalog implementation](../../ai-gateway/catalog/static_catalog.go) |
| Routing; selection; candidate | Chooses the configured model and, when applicable, an ordered primary/backup candidate. Selection is not proof of generation completion. | [Catalog construction](../../ai-gateway/pkg/internal/service/catalog.go) |
| Selection source; source | Where a selection's model and provider keys come from: `operator-catalog` (the configured catalog with server-held keys, including routed chains), `stack-catalog` (a stored stack catalog with its own keys) or `request-byok` (the request's own accounts). Selectors return models with their logical identity only; after selection, the runtime applies the logical observer configuration of the selection's source once per call. | [Selection](../../ai-gateway/internal/execution/selection.go) |
| Routing controls; `models`, `order`, `only`; request routing | Call-level `providerOptions.gateway` controls, named as in the Vercel AI Gateway, that compose one call's chain: fallback models after the requested one, providers to prefer, and providers to keep. They reorder, filter or extend authorized choices only; they never add credentials or destinations. | [Request routing](../../ai-gateway/pkg/internal/service/routed.go) |
| Model group; composed chain; expected attempt | A composed chain is one call's ordered physical candidates; each model group is the part of it from one requested model or `models` entry. The selection records each position's expected attempt: its destination and model. Attempt attribution is checked against them by position, and the routing summary groups attempts by their model. | [Routing composition](../../ai-gateway/pkg/internal/routing/compose.go) |
| Provider slug | The provider name `only` and `order` match: the `provider` value discovery and `gateway.execution` report, such as `anthropic` or a compatible provider's name. A configured provider instance name is not a slug. | [Route a call](../providers/grafana-gateway.md#route-a-call-to-other-models-and-providers) |
| Guard; policy; preflight; skills policy | A rule checked before some action, such as validating native options before a provider call. The skills policy is one: each configured candidate's `skills.allow` list, which the Anthropic native option guard applies per attempt; without it, the candidate refuses container skills. These names do not imply one global policy layer; check the actual placement and whether the plugin backend installs it. | [Native option guards](../../ai-gateway/pkg/internal/nativeoptions) |
| Refusal; aggregate chain failure | A refusal is a candidate that fails before native I/O because it cannot take the request, such as a disallowed skill. When several candidates fail, the call reports the call's cancellation or deadline first, otherwise the newest failure that is not a refusal; it is invalid request only when every candidate refused. | [Failure classification](../../ai-gateway/internal/execution/classify.go) |
| BYOK; bring your own key; request account | Provider credentials supplied for a request, distinct from the delegated token authenticating the caller. BYOK access (`cloud` mode) uses request-local Anthropic or OpenAI accounts; configured access uses configured catalog models and cannot switch to BYOK. | [Capability boundary](gateway-architecture.md#existing-code-versus-deployed-capabilities) |
| Admission control; aggregate capacity limit | Deciding whether to accept more work based on shared capacity, such as concurrent requests. Per-request byte and duration limits are not aggregate admission control. The plugin backend does not implement a general aggregate controller. | [Resource boundaries](gateway-architecture.md#streaming-failures-and-the-point-of-no-return) |

## Bytes and stream lifecycle

| Term and aliases | Meaning and why it matters | Code or further reading |
| --- | --- | --- |
| Unary; non-streaming | One complete model result returned as JSON. The handler can validate and encode it before committing success. A high-level SDK call that collects a stream is a different execution path. | [Request walkthrough](gateway-architecture.md#follow-one-request) |
| Serialization; encoding; decoding | Converts values to bytes or bytes back to values. JSON escaping and binary encoding can change size, so source-value size and encoded-response size are different measurements. | [Response encoding](../../ai-gateway/providerwire/v4/response.go) |
| Framing; SSE; Server-Sent Events | Delimits serialized events on a stream. ProviderWire uses `data: <JSON>` followed by a blank line. Sharing SSE framing does not make ProviderWire and UI message events interchangeable. | [Stream encoder](../../ai-gateway/providerwire/v4/stream.go) |
| Buffering; accumulation | Holding values or bytes before forwarding them. The handler buffers a unary result and individual encoded frames. That is different from buffering a complete provider stream to enable failover. | [Fallback guide](../guides/fallback-and-registry.md) |
| Decompression; content decoding | Expands compressed HTTP bytes, usually in a transport or provider client. Compressed length, decoded body length, and encoded Gateway frame length are different measurements; the model transport limits each provider response by its decoded length. | [Transport and resource boundaries](gateway-architecture.md#streaming-failures-and-the-point-of-no-return) |
| Response commitment; headers sent | The HTTP status and headers have been written. A subsequent failure cannot replace HTTP 200 with an error status; it needs a stream error if writing is still possible. | [Stream lifecycle](gateway-architecture.md#streaming-failures-and-the-point-of-no-return) |
| Candidate commitment; first-part selection | Default fallback accepts a provider on its first part, before Gateway's HTTP commitment. Even a start or error part selects it; later errors do not trigger replay. | [Fallback implementation](../../fallback/fallback.go) |
| Cancellation; abort; deadline; timeout | Cancellation asks work to stop; a deadline bounds elapsed work. The request deadline, set by Grafana's route deadline, covers selection and execution, while stream idle time limits gaps between parts. Cancellation cannot reverse remote effects. | [Stream lifecycle](gateway-architecture.md#streaming-failures-and-the-point-of-no-return) |
| Drain; cleanup | Consumes leftover channel values after stopping normal output, so producers can release resources. The Gateway execution runtime owns every returned stream's cleanup and bounds its draining by time. | [Execution runtime](../../ai-gateway/internal/execution/runtime.go) |
| Server-side fallback; Anthropic `fallbacks`; `serverFallbacks` policy | Anthropic retrying a refused turn on another model inside one native request, within one Gateway attempt. It is not Gateway fallback to the next candidate, routing `models`, retry, or the configured fallback candidate identity that `gateway-ordered-text-fallback` defines. Configured candidates admit it only within their `serverFallbacks` policy; request accounts forward it unchanged. | [Server-side fallback](../providers/grafana-gateway.md#use-anthropic-server-side-fallback) |
| Retry; fallback; replay | Retry repeats a call, often to the same provider. Fallback tries another configured candidate after an eligible failure. Replay repeats already-started work or output. None guarantees exactly-once remote execution; retries may also occur inside native clients. | [Retry guide](../guides/retry-and-timeout.md), [fallback guide](../guides/fallback-and-registry.md) |
| Response segment; sequential response; message | The parts from one `response-metadata` to the next within one provider stream. Text and reasoning IDs are unique within a segment; tool and approval IDs are unique within the stream. A `finish` ends a segment, not the stream. The execution runtime enforces the segment rules. | [Stream validator](../../ai-gateway/internal/execution/stream_validation.go) |
| Error event; terminal failure | A provider error event can precede more content and finish. A handler-terminal failure ends processing. An HTTP success status does not distinguish these stream outcomes. | [Streaming tests](../../ai-gateway/providerwire/v4/stream_test.go) |

## Observation and accounting

| Term and aliases | Meaning and why it matters | Code or further reading |
| --- | --- | --- |
| Logical call; invocation | One call to the selected public model. It may contain multiple physical candidate attempts. Tool continuation and application retries create new invocations. | [Operator observation](../../ai-gateway/docs/text-observability.md) |
| Physical attempt; candidate attempt | An observed try of a configured candidate or request key, at most 8 per request. It is not necessarily one network request: provider-side execution can add work beneath it, although native client retries are disabled. | [Attempt observation](../../ai-gateway/pkg/internal/service/physical_attempts.go) |
| Diagnostics; execution overview; native error summary | Optional evidence about decisions and failures. `gateway.execution` describes observed configured or BYOK account attempts in order; BYOK overviews have no canonical model or provider instance. The selected attempt's `servedModelId` names the model that answered after an Anthropic server-side fallback. It is not a full trace, completion guarantee, or replay authorization. Its absence does not prove no attempts occurred. | [Execution overviews](../providers/grafana-gateway.md#inspect-execution-overviews-and-failures) |
| Routing summary; `gateway.routing` | The execution overview's attempts grouped by model, with a subset of the Vercel AI Gateway's routing field names. It travels with the overview and adds only which model each attempt belongs to; `success` means selected, not completed. | [Routing projection](../../ai-gateway/internal/execution/routing.go) |
| Usage; token accounting | Provider-reported input/output and related token counts. Counts may be unavailable on failure and do not establish total billing across hidden retries or remote effects. | [Usage transport](../../ai-gateway/providerwire/v4/response.go) |
| Provider metadata; namespace; opaque data | Provider-specific values carried alongside common output. A namespace is a map key, not authority: native values named `gateway` do not automatically become trusted Gateway diagnostics. | [Metadata boundaries](../providers/grafana-gateway.md#inspect-execution-overviews-and-failures) |
| Observability; telemetry; capture | Logs, metrics, traces, or optional content recording for operators. This is separate from client-facing diagnostics; enabling one does not imply the other, nor permission to expose content to a browser. | [Operator observation](../../ai-gateway/docs/text-observability.md) |
