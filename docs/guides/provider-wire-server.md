# Serving provider-wire models

Provider wire centralizes model access behind a service-to-service HTTP endpoint.
This repository has two deliberately separate server packages:

- `gateway/providerwire` is the established tolerant transport. It supports
  unary generation and streaming SSE and remains the transport used by the
  Grafana provider.
- `gateway/providerwire/v4` is the strict ProviderWire V4 boundary. Its current
  production surface accepts unary `DoGenerate` only, validates against the
  checked-in V4 contract, and rejects streaming requests.

Browser chat endpoints use the UI stream helpers in
[Streaming over HTTP](streaming-http.md), not either provider-level endpoint.

## Mount the complete legacy transport

Use the legacy handler when existing Go clients, Grafana, or provider-level
streaming compatibility is required:

```go
resolver := providerwire.ModelResolverFunc(
	func(r *http.Request, modelID string) (provider.LanguageModel, error) {
		return resolveModel(r.Context(), modelID)
	},
)

handler, err := providerwire.NewHandler(
	resolver,
	providerwire.WithTotalTimeout(2*time.Minute),
	providerwire.WithIdleTimeout(time.Minute),
	providerwire.WithMaxRequestBodyBytes(8<<20),
)
if err != nil {
	return err
}

mux.Handle(providerwire.PathLanguageModel, authenticate(handler))
```

This handler is path-agnostic and supports unary JSON and streaming SSE. Its
existing defaults, wire bytes, and tolerant decoding are independent of the V4
handler.

## Mount the strict V4 unary transport

Construct the strict handler with its request-aware resolver. It requires the
exact `/language-model` path, so strip a host-owned prefix before dispatch:

```go
resolver := providerwirev4.ModelResolverFunc(
	func(r *http.Request, modelID string) (provider.LanguageModel, error) {
		return resolveAuthorizedModel(r.Context(), modelID)
	},
)

handler, err := providerwirev4.NewHandler(
	resolver,
	providerwirev4.WithTotalTimeout(2*time.Minute),
	providerwirev4.WithMaxRequestBodyBytes(8<<20),
	providerwirev4.WithMaxInlineFileBytes(8<<20),
	providerwirev4.WithMaxResponseBodyBytes(8<<20),
)
if err != nil {
	return err
}

const prefix = "/internal/providerwire/v4"
mux.Handle(
	prefix+providerwirev4.PathLanguageModel,
	authenticate(http.StripPrefix(prefix, handler)),
)
```

The package godoc is authoritative for the constructor, options, constants, and
defaults. The strict handler embeds the checked-in schemas and needs no schema
files at runtime.

## Keep host policy around the handler

The host remains responsible for:

- authentication and authorization before dispatch;
- tenant and user identity;
- deciding which public model IDs a caller may resolve;
- route prefixes and stripping them before the strict handler;
- transport header, read, write, and idle deadlines;
- rate limits, billing, logging, audit policy, and public deployment behavior.

Outer HTTP headers remain available to authentication middleware and the V4
resolver. They are not copied into `provider.CallOptions`. Do not let a
client-controlled model ID bypass the same allowlist used by model discovery.

## Understand the strict V4 policy

The V4 handler performs envelope, raw-body, strict JSON syntax, schema, private
decode, policy, adaptation, and resource checks before resolving a model. It
accepts the pinned orchestration user-agent marker generated by `ai.generateText`
but removes it before provider invocation. Other non-empty call-option header
maps are rejected.

The handler also rejects Gateway routing controls, nested reserved Gateway
namespaces, raw-chunk intent, unsupported or lossy numeric adaptations, and
resources over configured bounds. Allowed provider-option namespaces remain
opaque, and explicit empty collections are preserved where the Go provider
domain can represent them.

A request selecting streaming is rejected before resolution. Use the complete
legacy handler for SSE; the V4 package does not currently provide `DoStream`, a
Go client, or Grafana transport adoption.

## Bound work and handle cancellation

For V4, one total-timeout context starts after request and policy acceptance and
covers both resolution and the single `DoGenerate` call. Request cancellation
propagates through that same context. The handler can return a timeout response
when an implementation ignores cancellation, but resolvers and models must
honor context cancellation to release their own resources promptly.

Host HTTP server settings still own transport-level deadlines. The legacy
handler additionally has an idle timeout for streaming calls; that option does
not apply to the unary-only V4 handler.

## Treat V4 responses as a disclosure boundary

The V4 result projection preserves contract-safe content, finish reason, usage,
warnings, and safe response identity/timestamp fields. It removes provider
metadata, raw usage, backend request and response details, provider identity,
and backend model IDs. Complete success and error bodies are bounded and
validated before commitment.

Failures use a closed, privacy-safe Gateway error shape. Provider API error
URLs, headers, bodies, data, credentials, causes, and diagnostic messages are
not returned to callers. Keep richer diagnostics in host-side observability;
do not depend on the public response for backend details.

## Resolve public model IDs

Adapt a [gateway model catalog](gateway-model-catalog.md) when clients should use
stable public names. Preserve `ResolvedModel.ID` for policy and logs even though
the handler ultimately needs only the resolved `LanguageModel`. Authentication
and model authorization belong before or inside the resolver, not in either
provider-wire package.
