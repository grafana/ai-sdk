# Design

## Context

See proposal.md. `streamAdapter.handleEvent` (`providers/anthropic/convert_stream.go`) sends `PartFinish` inside the `message_delta` case and only clears `messageOpen` on `message_stop`. Upstream (`anthropic-language-model.ts` at `5d12eaa6`) mutates stream-level `finishReason`, usage and metadata state on `message_start`/`message_delta` and enqueues the only `finish` in `message_stop`; its transform has no `flush`. For `error` chunks it enqueues the error and keeps reading; an error as the first chunk is converted to a thrown `APICallError`. Upstream `streamText` marks the step terminal on `error`, sets finish reason `error`, and a later `model-call-end` overwrites the step finish reason.

In Go, `pumpMessageStream` converts an `error` frame into a terminal `item.err`, and `consumeStreamParts` returns on any item error. `StreamText` sets `terminated` and `providerFailed` on `PartError` and keeps looping until the stream closes; `completed` is set by a later `PartFinish`.

Existing conformance replays only `streamText` -> UI chunks, request snapshots and usage. Of 50 Anthropic fixtures, 47 have one start/delta/stop per message, so they cannot distinguish finish timing; only `programmatic-tool-calling`, `duplicate-message-start` and `spliced-message-start` discriminate.

## Goals / Non-Goals

**Goals:**
- Executable, upstream-generated evidence of provider-part sequences, written and failing before the fix.
- One `PartFinish` per `message_stop`; raw/finish ordering and error handling identical to upstream at the provider-part level.

**Non-Goals:**
- Gateway handling of sequential messages (#393).
- OpenAI/Bedrock adapters.
- Synthesizing a finish at EOF.
- Proof of live Anthropic behavior (this is mock-stream evidence).

## Decisions

1. **Provider-parts golden is always on for Anthropic.** Every Anthropic provider case has `expected-provider-parts.jsonl`, generated and compared unconditionally, so there is no per-fixture switch to maintain and every fixture adds evidence (finish reason, usage, finish metadata, part order, raw order), not just finish timing. Parts are captured by a recording wrapper around the model during the existing `streamText` run, so multi-step fixtures (`input-N.chunks.txt`, 21 of them) yield one entry per model call; a direct single `doStream` call could not. The wrapper forces raw chunks at the model boundary so one golden covers raw ordering. Go does the same with a recording model decorator. Comparison normalizes only what cannot match: generated IDs, the Go-only `provider`/`responseHeaders`/`usage` fields on response-metadata (Go carries them in process where the TypeScript SDK returns them on the result object), a timestamp derived from the HTTP `Date` header, absent versus false `isError` (Go's bool cannot express absence), and the content of errors without a provider status (Go phrases its own errors in the repository's lowercase style). Provider errors compare message, status and retryability. Alternative: opt-in sidecar on discriminating fixtures. Rejected: extra control surface, less evidence. Alternative: assert counts in Go unit tests only. Rejected: no upstream oracle, which is how the original bug was pinned. The runner and generator take a per-provider capability; it is enabled for Anthropic, Bedrock, OpenAI and OpenAI-compatible, the providers that have conformance fixtures. Bedrock cases using the non-streaming generate operation have no stream parts and no golden.

2. **Triage instead of hiding.** Always-on will likely expose differences unrelated to #377 (for example the per-message metadata reset). Differences caused by this change are fixed here. Others are classified per `AGENTS.md` (parity-preserving adaptation, intentional deviation, bug, coverage gap), recorded in `PARITY.md`, and registered as `upstream-sync` issues; the affected case is listed on an explicit allowlist in the runner with its issue number so it is visible and never silently skipped. Raw-chunk forcing must not change `expected.jsonl`; task 1.3 verifies UI goldens are unchanged, with a separate second replay as fallback if they move.

3. **Synthetic cases live in `test/conformance/testdata/anthropic-stream-parts/`**, following the `testdata/request-snapshots/` precedent, not under `recorded/` or `upstream/`. `cases.json` carries labeled synthetic SSE inputs; expected parts are generated by the pinned upstream TypeScript; Go compares. Alternative: Go unit tests with hand-copied expectations. Rejected as the primary mechanism because expectations would not be regenerated on baseline upgrades. `AGENTS.md` places synthetic provider responses in unit or `ui/` tests; this extension of the `testdata/` precedent is a judgement call to confirm in review, with the unit-test fallback if rejected.

4. **Build finish at `message_stop` from adapter state.** `message_delta` only updates state; `message_stop` builds and emits. Alternative: compute at each delta and cache. Rejected: the delta-less message still needs a stop-time build, so two paths.

5. **Finish reason and output usage are stream-level as upstream** (initial `other`/empty raw; non-null `message_start.stop_reason` and each delta overwrite; not reset per message). `message_start` sets only input and cache counters; output tokens, thinking tokens and iterations persist from earlier deltas, so a message without a delta reuses them. The provider-parts golden showed Go previously reset these at `message_start`. Metadata and the safeguard verdict keep their per-message reset, which `anthropic-safeguards` already requires and which differs from upstream's stream-level carry-over; record it in `PARITY.md`.

6. **Validate safeguard results at `message_delta`, build metadata at `message_stop`.** Preserves the requirement that a malformed verdict errors on its own delta. Alternative: error at stop. Rejected: moves where the error surfaces.

7. **API `error` frames become non-terminal; transport/decode errors stay terminal.** The pump distinguishes the two; an error frame emits a `PartError` and reading continues, the first-frame case keeps failing `DoStream` (existing preflight, verified by a synthetic case). Alternative: keep terminal and record a deviation. Rejected at the user's direction: we align with upstream.

8. **Core handling of error-then-finish is decided by a golden, not assumed.** A provider-independent `test/conformance/ui/` fixture feeds `error` then `finish` parts through upstream `streamText` and Go `StreamText`. If Go already matches, no core change. If not, the mismatch is reported to the user before touching `streamtext.go`; a small fix may be included in this change, a larger one becomes an `upstream-sync` work package and this change's Anthropic error behavior waits on it.

9. **Bedrock raw chunks follow upstream's envelope.** Upstream's raw value is `{[eventType or exceptionType]: payload without p}`. Go previously forwarded the bare payload, so raw consumers could not tell which event a chunk was. Go now wraps and drops `p`. Alternative: normalize the difference away in the harness. Rejected: it would hide a loss of information rather than fix it.

10. **Tool-call input strings are serialized as upstream does.** Upstream builds them with `JSON.stringify` in schema field order; Go used `json.Marshal` over maps, which escapes `<`, `>`, `&` and sorts keys. A shared helper encodes without HTML escaping, and apply-patch and local-shell use ordered structs. The strings are semantically equal either way, but consumers that compare or display the raw string saw a difference. Alternative: compare `input` as parsed JSON in the harness. Rejected for the same reason as decision 9.

11. **Adapters stop emitting duplicate identity fields on tool-input parts.** Bedrock and OpenAI-compatible set `toolCallId` (and on OpenAI-compatible, `toolName` on delta and end) beyond the V4 shape. Consumers read `id`, so removal is safe.

12. **OpenAI finish reports the created response ID.** Upstream uses the ID from `response.created`; Go used the `response.completed` payload. The two only differ when a stream rotates IDs.

13. **Anthropic errors use upstream's classification everywhere.** Upstream maps each error type to a status and retryability for both the first-chunk error and mid-stream error parts. Go classified the first chunk as 500 and retryable only for `api_error` and `overloaded_error`, and mid-stream errors as status 200 with the SDK's `POST ...` message. One table now serves both paths, so rate limits become 429 and retryable and invalid requests 400. This changes what retry layers see for `rate_limit_error`.

14. **Raw usage iterations keep the declared fields.** Upstream's strict iteration schema drops everything else; Go passed the nested `cache_creation` breakdown through. The adapter now filters to the six declared fields.

15. **No finish without `message_stop`.** EOF after `message_delta` yields no finish; `StreamText` takes its partial/no-output path, same as upstream's incomplete-stream handling.

## Risks / Trade-offs

- [Truncated streams were "completed" in `StreamText`] -> now partial/no-output, intentional and covered by tests.
- [Continuing after an error frame could surface a finish after an error in Go] -> gated by decision 8 before merging.
- [Existing tests lack `message_stop`] -> mechanical but wide; compile-level failures guide the edits.
- [Stale finish reason and output usage across delta-less messages] -> matches upstream; asserted by the golden and synthetic cases.
- [Differences found by the always-on golden] -> investigated per provider. Real adapter deviations are fixed (Bedrock raw envelope and extra `toolCallId`; OpenAI input escaping, field order and finish response ID; OpenAI-compatible extra tool-input fields). Wire-shape differences are fixed in `StreamPart.MarshalJSON` (`stream-start` warnings, millisecond UTC timestamps). Anthropic error frames and raw usage iterations are aligned with upstream. Only the inherent differences listed in decision 1 remain normalized. The allowlist is empty.
- [Synthetic inputs are not live evidence] -> labeled as such; no claim that Anthropic sends `message_stop` after an error.
- [Generating goldens needs `mise deps` and the pinned TS packages] -> generation is a normal workflow step; expectations are committed.
