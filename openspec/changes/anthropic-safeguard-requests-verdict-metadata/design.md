## Goals / Non-Goals

**Goals:**
- Preserve upstream omission, nonempty request projection, classifier context, beta deduplication, optional result shape and last non-null streaming verdict with both entry points.
- Keep provider metadata scoped to `anthropic.safeguardResults`, validate malformed response values, and prove the SDK transport and Go option JSON round trip with focused tests.
- Keep opt-in use conditional on provider authorization/support; establish a green candidate-source provider delivery and honest evidence boundary.

**Non-Goals:** Automatically enable classification, enforce a safety policy or gate tool execution based on a verdict; change `provider.LanguageModel`, tool-call metadata, generic SSE chunks, or SDK-wide JSON mapping; assert Vertex or direct live-provider support without provider confirmation. Issue #216's generic request controls and message options remain separate.

## Decisions

1. **Typed model-level input and opt-in preflight.** Extend `AnthropicOptions` with `Safeguards []AnthropicSafeguard` (`json:"safeguards,omitempty"`); each entry has a typed `AnthropicSafeguardType` discriminator with constant `AnthropicSafeguardDangerousToolUse = "dangerous_tool_use"` and optional `ClassifierContext *map[string]json.RawMessage` (`json:"classifierContext,omitempty"`). A non-nil pointer to an empty map preserves explicit `{}` through typed option serialization; nil omits the field. Reject a non-nil pointer to a nil map on the typed path, since it serializes as `classifierContext: null`. Before `provider.ResolveOption[AnthropicOptions]`, inspect only the raw Anthropic option's `safeguards` field and configured entries' `classifierContext` field for explicit JSON `null`: reject both before HTTP, since the registered upstream optional array/record schemas reject null and Go's ordinary unmarshaling erases its presence. Preserve absent and empty safeguards as omission. Then resolve and validate the typed values, rejecting malformed or unsupported safeguard entries and invalid raw JSON values before HTTP without broadening unrelated option validation. Verify typed options and `RawProviderOption` round trips behave alike. Upstream Zod rejects such provider options; this narrow preflight does not introduce validation for unrelated fields. Alternative: `map[string]any` allows non-JSON Go values and delayed transport errors; raw maps align with existing opaque-JSON idioms.

2. **Overlay only the missing request field.** For nonempty validated options, map `type` verbatim and optional `classifierContext` to wire `classifier_context` (including `{}` if present), and append `option.WithJSONSet("safeguards", projectedEntries)` to `buildResult.requestOptions` in `buildParamsWithCapabilities`. Add the exact beta to `p.Betas` via `appendBetaUnique` alongside existing provider betas. For absent or empty safeguards, do neither; a caller explicitly requesting a beta via `Betas` remains authoritative, so absence only means no **automatic** beta. The SDK serializes `p` before applying request options in both `Beta.Messages.New` and `NewStreaming` (`model.go:100-148`); capture actual HTTP bodies and headers to prove overlay ordering with other request options and user betas, including Vertex-capability calls. Alternative: upgrade the SDK just for a field it does not yet publish, or fork it; neither is needed if the existing overlay is confirmed. If it is not compatible with either transport, stop and choose a compatible mapping before implementation proceeds. Avoid any new root-module dependency.

3. **Whitelisted, validated returned results.** Extend `buildAnthropicProviderMetadata` to inspect only `safeguard_results` in the raw unary message (`convert_response.go:465-477`) and merged message deltas (`convert_stream.go:460-481`). Omit `safeguardResults` for absent or null; retain a present empty array. Validate the pinned schema shape (array of objects with string `type`, object `status` with string `type`, optional/null `tool_uses` map keyed by tool id and string `type`/optional-null string `outcome` and `explanation` for each verdict). Project only these known fields, preserving the API's snake_case nested keys and unknown string discriminator values; strip unrelated raw fields as upstream Zod object parsing does. On invalid present data, return a contextual conversion error in unary, or emit the existing `PartError` through `consumeStream` in streaming, without including raw verdict contents in the error. Do not rely on typed SDK fields that discard the new response. The result is generation/finish metadata only, not per-tool-call part metadata. Alternative: copying the entire `RawJSON()` into provider metadata would expose unrelated fields and bypass response validation.

4. **Keep the last non-null stream value.** Keep a separate stream verdict state sourced only from `message_delta.delta.safeguard_results`, not from `message_start`'s raw metadata map. Preserve the latest validated non-null delta verdict across later absent/null deltas, overwrite it for a subsequent non-null array (including `[]`), and reset it on new `message_start`; `buildAnthropicProviderMetadata` then projects that state on finish. A verdict appearing only in `message_start` must never be projected, even if the next delta omits or nulls the field. The existing adapter emits `PartFinish` on `message_delta` rather than at upstream `message_stop`; retain that pre-existing event-timing behavior in this focused change, but assert the **last** finish in multi-delta tests carries the final verdict and check that `StreamText`'s final step metadata receives it. Do not pretend earlier finish parts have the final verdict. Moving all Anthropic finishes to `message_stop` is an unrelated lifecycle rewrite affecting existing tests/partial streams; if this timing prevents final-result parity, resolve it explicitly rather than publishing a false parity claim.

5. **Prove the boundary without invented recordings.** Add test cases for typed/raw option round trips (including typed explicit `{}`), missing/empty/configured safeguards and rejection of explicit safeguards/context null, beta deduplication on unary/stream, actual fake-HTTP body/header capture, direct/Vertex-capability serialization, absent/null/empty/present unary verdict, multiple streaming deltas (null → value → null and value → newer value), message_start-only verdict exclusion, malformed payload, unrelated-field stripping and a mocked transport failure. Use `convert_request_test.go`, `convert_response_test.go`, `convert_stream_test.go`, and existing fake HTTP patterns; include a focused high-level `StreamText` check if necessary to verify last-step metadata. Provider fixture input in `recorded/` must be unmodified live capture; `upstream/` must be byte-identical indexed registered upstream input. If provider access is unavailable, document lack of live evidence under the issue's acceptance, not as synthetic conformance. The existing UI chunk contract does not serialize finish-step provider metadata (`streamtext.go:350-380`); verify no frontend wire behavior changes before deciding whether the cross-language integration rule applies. If frontend chunks do change, add a deterministic Go testserver scenario and matching Vitest schema-parse/assembled-message test.

## Risks / Trade-offs

- [The SDK may reorder options or serialize an overlay incorrectly] → Capture real unary/stream HTTP request bytes with existing SDK v1.75.0; block delivery if verified transport cannot carry the field.
- [Synthetic responses may be parsed differently from live Anthropic responses] → Compare field validation and retention to exact pinned TS source/tests and keep `PARITY.md` coverage mixed; obtain provider permission before claiming production use, and record unmodified live events only when access is available.
- [Upstream emits one finish at `message_stop`; Go emits each delta] → Test last-finish/final-step semantics explicitly; no lifecycle change or upstream-identical finish count claimed in this proposal.
- [Opaque classifier context could contain secrets or unexpected JSON] → Treat it as caller-supplied data; forward only when explicitly configured and never log it or copy the full returned message into provider metadata.

## Migration Plan

No changes to calls that omit `safeguards`; the beta and wire field stay absent automatically. Existing clients need no data migration. Callers opting in must confirm the Anthropic beta is available for their credential/model and accept that provider rejection is surfaced via existing API/stream errors, not silently retried without safeguards. Document the new option and the returned metadata in Anthropic godoc and the provider guide, including that classification is not a tool-execution policy. Delivery stays in the separately tested Anthropic module; validate provider tests and `mise run parity-check` against candidate source. Rollback consists of removing the opt-in mapping and projection as a unit; existing baseline calls continue unchanged.
