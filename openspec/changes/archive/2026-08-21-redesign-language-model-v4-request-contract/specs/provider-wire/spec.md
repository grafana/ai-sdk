## ADDED Requirements

### Requirement: Legacy request adapter preserves the redesigned provider domain

The tolerant `gateway/providerwire` package SHALL map between `provider.CallOptions` and a complete private request-only legacy representation explicitly. It SHALL NOT treat `encoding/json` output of provider request structs as protocol authority. The adapter SHALL preserve exact integer and finite floating `LanguageModelNumber` variants, optional boolean and string presence, request-file filename presence, file-data discriminators, system-message legacy behavior, tool results, and opaque provider options. Decoding SHALL preserve explicitly present empty collections. Encoding SHALL retain the parent's `omitempty` collapse for non-nil empty collections because preserving those parent bytes takes precedence over an impossible provenance-free encode round trip.

The adapter MUST NOT change response, stream, or error representations or codecs, add a strict mode, or import a future `gateway/providerwire/v4` representation. Invalid `LanguageModelNumber` zero values, non-finite numbers, and redesigned values with no legacy representation SHALL return errors rather than be silently concatenated, discarded, rounded, or reinterpreted.

The tolerant legacy adapter SHALL NOT apply future strict selected-arm validation to values the parent encoder accepted. It SHALL preserve the parent's emission and precedence behavior for populated inactive fields and for `DataContent.Reference` containing any valid JSON. Direct provider request mappers and the future strict V4 mapper remain responsible for rejecting invalid selected-arm state.

#### Scenario: Redesigned scalar presence round-trips
- **WHEN** a legacy request carries explicit false, explicit empty optional strings, or fractional numeric settings supported by its request JSON shape
- **THEN** `EncodeCallOptions` followed by `DecodeCallOptions` SHALL preserve those provider values

#### Scenario: Empty inline text file data round-trips
- **WHEN** a request carries publicly constructed `{type:"text",text:""}` file data
- **THEN** legacy request encoding and decoding SHALL preserve the selected text arm and empty payload

#### Scenario: Explicit wire empty collections survive decoding
- **WHEN** legacy request bytes explicitly contain an empty optional array or object member
- **THEN** the decoder SHALL produce a non-nil empty collection

#### Scenario: Parent empty-collection emission remains collapsed
- **WHEN** encoding receives a non-nil empty collection that the parent encoder omitted through `omitempty`
- **THEN** the redesigned tolerant encoder SHALL omit it identically
- **AND** tests SHALL NOT claim provenance-free encode/decode preservation for that value

#### Scenario: Historical system behavior remains legacy-only
- **WHEN** the tolerant legacy adapter encounters a historically accepted system shape
- **THEN** its existing legacy behavior MAY remain for compatibility
- **AND** that behavior SHALL NOT define or weaken the future strict V4 mapper

#### Scenario: Parent-permissive inactive fields remain byte-compatible
- **WHEN** a migrated parent value contains function-tool provider fields, content-part fields from multiple arms, or another flat inactive field that the parent encoder emitted
- **THEN** the tolerant adapter SHALL reproduce the parent bytes
- **AND** it SHALL NOT treat legacy byte preservation as strict protocol validity

#### Scenario: Parent-permissive reference JSON remains byte-compatible
- **WHEN** a migrated parent `DataContent.Reference` contains valid JSON that is not a string-valued object
- **THEN** the tolerant adapter SHALL reproduce the parent encoder's reference bytes
- **AND** direct provider or future strict mapping MAY reject that value

#### Scenario: Unrepresentable redesigned value fails
- **WHEN** a redesigned provider request value has no lossless legacy representation
- **THEN** encoding SHALL return an error rather than normalize the value silently

### Requirement: Pre-redesign legacy request compatibility is parent-pinned and byte-stable

The historical compatibility baseline SHALL be parent commit `32e5ab7f1ab9e524477cc0ece04c690a89854a24`. The parent byte-stability domain SHALL mean every `provider.CallOptions` value for which that parent's `EncodeCallOptions` returned bytes. The corresponding redesigned value SHALL be defined by a migration projection that replaces changed fields with equivalent redesigned values, including moving parent request-file `Filename` into `FilePartFilename`, while preserving every other populated flat field. The domain includes mixed inactive-arm state and arbitrary valid-JSON `DataContent.Reference` payloads emitted by the parent.

Before provider request types change, the repository SHALL commit a request compatibility corpus generated by that parent implementation. Fixture metadata SHALL record the parent commit, parent-produced canonical request bytes, migration projection, and parent decode outcome. When parent decoding succeeds, metadata SHALL include its semantic projection; when it fails, metadata SHALL record that rejection rather than claiming previous-decoder support.

For every value in the defined parent encoder domain, redesigned `gateway/providerwire` SHALL contractually emit byte-identical request output. The corpus SHALL cover finite field/arm equivalence partitions, including permissive inactive-arm and reference-shape cases. Parent-produced bytes plus post-redesign equality prove encoder compatibility for corpus rows. Previous-decoder compatibility SHALL be claimed only for the parent-decodable subset and proved from the recorded parent projection, never from a redesigned encode/decode self-test. Newly representable distinctions SHALL NOT be described as historical byte-stability guarantees.

#### Scenario: Historical large integer golden remains unchanged
- **WHEN** a parent request carries an integer outside the exact IEEE-754 integer range
- **THEN** redesigned encoding SHALL equal the exact parent-produced decimal bytes

#### Scenario: Historical request corpus remains unchanged
- **WHEN** any parent-corpus `CallOptions` value is encoded after the redesign
- **THEN** its canonical bytes SHALL equal the parent-produced fixture bytes

#### Scenario: Parent decoder evidence is independent and bounded
- **WHEN** previous-decoder compatibility is evaluated for a corpus row
- **THEN** the evidence SHALL claim acceptance only when the parent decoder succeeded and recorded its semantic projection before redesign
- **AND** it SHALL retain parent rejection outcomes without relabeling them as decoder-compatible
- **AND** it SHALL NOT infer previous-decoder support from a redesigned encode/decode round trip

#### Scenario: Parent-permissive corpus partitions are represented
- **WHEN** the parent corpus is generated
- **THEN** it SHALL include representative mixed tool/content inactive fields and non-string-valued valid JSON references accepted by the parent encoder
- **AND** redesigned encoding SHALL reproduce their parent bytes

#### Scenario: Redesigned decoder reads supported parent corpus rows
- **WHEN** the current tolerant decoder receives a parent-produced fixture row supported by the legacy decode dialect
- **THEN** it SHALL recover the equivalent redesigned provider-domain value as current regression coverage
- **AND** that acceptance SHALL NOT establish future strict validity

#### Scenario: New values have a bounded claim
- **WHEN** an explicit false, empty optional scalar, fractional number, or empty inline-text arm is encoded
- **THEN** tests SHALL claim redesigned-adapter behavior only
- **AND** they SHALL NOT relabel the value as previously representable

## MODIFIED Requirements

### Requirement: Single endpoint with streaming header switch

The wire package SHALL expose a single HTTP endpoint path constant `PathLanguageModel = "/language-model"`. Both `DoStream` and `DoGenerate` SHALL be transported via `POST` to that path. The body SHALL be produced by `EncodeCallOptions`, which explicitly adapts transport-neutral `provider.CallOptions` to the tolerant legacy request dialect. The HTTP request SHALL distinguish unary from streaming via the `ai-language-model-streaming` header with boolean string `true` or `false`.

#### Scenario: Generate request shape
- **WHEN** the client transports a `DoGenerate` call
- **THEN** the request SHALL be `POST /language-model` with header `ai-language-model-streaming: false`, header `ai-language-model-id: <modelID>`, header `ai-language-model-specification-version: 4`, and body equal to the bytes returned by `EncodeCallOptions`

#### Scenario: Stream request shape
- **WHEN** the client transports a `DoStream` call
- **THEN** the request SHALL be `POST /language-model` with header `ai-language-model-streaming: true`, the same model-id and spec-version headers, and body equal to the bytes returned by `EncodeCallOptions`

#### Scenario: Provider generic JSON is not used directly
- **WHEN** a legacy client builds either request
- **THEN** it SHALL NOT obtain the HTTP body by directly marshaling `provider.CallOptions`

### Requirement: Request/response envelope helpers

The wire package SHALL export the following helpers and MUST use them at every encode/decode site:

- `EncodeCallOptions(opts provider.CallOptions) ([]byte, error)`
- `DecodeCallOptions(data []byte) (provider.CallOptions, error)`
- `EncodeGenerateResult(result *provider.GenerateResult) ([]byte, error)`
- `DecodeGenerateResult(data []byte) (*provider.GenerateResult, error)`
- `EncodeAPICallError(err *provider.APICallError) ([]byte, error)`
- `DecodeAPICallError(data []byte) (*provider.APICallError, error)`

The call-options helpers SHALL own explicit mapping between provider request values and the private request-only legacy representation. Generate-result, stream, SSE, and API-call-error helpers and their inherited tests SHALL retain their existing behavior without new Phase 2 scope.

#### Scenario: CallOptions round-trip
- **WHEN** `provider.CallOptions` carries `Prompt`, `Tools`, `ToolChoice`, `MaxOutputTokens`, `Temperature`, `Reasoning`, `ResponseFormat`, `StopSequences`, `Headers`, `ProviderOptions`, and the redesigned optional presence states, excluding parent-collapsed non-nil empty collections
- **THEN** the decoded value SHALL be equal to the original with no supported field loss

#### Scenario: GenerateResult round-trip
- **WHEN** a `provider.GenerateResult` carries `Content`, `FinishReason`, `Usage`, `ProviderMetadata`, `Warnings`, `Request`, and `Response`
- **THEN** the decoded value SHALL be equal to the original with no response-field loss

#### Scenario: APICallError round-trip
- **WHEN** a `provider.APICallError` carries `Message`, `StatusCode`, `URL`, `RequestBodyValues`, `ResponseHeaders`, `ResponseBody`, `IsRetryable`, and `Data`
- **THEN** the decoded value SHALL be equal to the original, with cause intentionally not preserved across the wire

#### Scenario: Request mapping is transport-owned
- **WHEN** provider request structs change without changing legacy semantics
- **THEN** the private adapter SHALL absorb the source change while canonical legacy bytes remain stable
