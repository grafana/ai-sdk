## Context

Issue #222 concerns only Bedrock Converse. Baseline is `@ai-sdk/amazon-bedrock` 5.0.88 at `08ae5ad05bc12496dd1ffcf64e34419e0831300d`; the pinned raw implementation and tests match the local extracted target byte-for-byte (six relevant files checked). Reference seams: upstream `amazon-bedrock-anthropic-model-support.ts`, `amazon-bedrock-chat-language-model.ts` and its tests, `amazon-bedrock-prepare-tools.ts`, `convert-to-amazon-bedrock-chat-messages.ts` and tests, and `@ai-sdk/anthropic/internal` model capabilities/schema tooling. In Go, `buildRequest` resolves `BedrockOptions`, root reasoning, tools, output routing, additional fields and response metadata; `convertPrompt` builds document/cache blocks. The current blacklist only gates some native JSON cases, strict schemas are not checked recursively, OpenAI effort is flat, and document names are not sanitized. `PARITY.md` classifies provider-adapter evidence as mixed.

## Goals / Non-Goals

**Goals:** Match pinned Converse request semantics and synthetic JSON-tool response handling across generate/stream; preserve existing Go idioms and legacy `bedrock` namespace; test dated/regional and profile IDs, reasoning budgets, option precedence, strict/failure paths and cache/beta/tool choice.

**Non-Goals:** Mantle, Anthropic Invoke, guessed live-provider recordings, new root/provider-contract APIs, or changing the baseline pin.

## Decisions

1. **Model-family identification (API proposal, owner approval required before implementation):** Propose a Bedrock constructor option `WithModelFamily` accepting only the Anthropic family (typed enum), analogous to upstream's model-scoped `AmazonBedrockChatModelSettings.modelFamily` rather than a request-level `BedrockOptions.modelFamily`. The Go `New(modelID, opts ...Option)` constructor already holds read-only model settings via `WithRegion` and similar options; `BedrockOptions` instead carries per-call options. Keeping family model-scoped avoids changing its identity between calls on the same model. This is a proposed public API, not an approval conferred by issue registration; obtain OpenSpec/owner approval for this shape before implementing it. Determine Anthropic identity from explicit family, ID containing `anthropic`, or `:application-inference-profile/` **and explicitly configured** `reasoningConfig.budgetTokens` (before derived root reasoning). Reuse this result for thinking, tools, response paths and output. Keep unknown profile IDs unknown unless specified; explicit family allows native `auto` despite missing ID capability. Compare root reasoning against upstream `getModelCapabilities` for dated/regional IDs: known older non-adaptive Claude families (including Sonnet/Opus 4.x before 4.6) use their pinned budget maxima, Sonnet/Opus 4.6 use adaptive thinking, unknown IDs containing `claude-` use adaptive thinking with a 128000-token maximum, and unknown non-Claude IDs identified as Anthropic use the conservative 4096-token budget fallback. Alternative: infer all profile ARNs as Anthropic; unsafe for non-Anthropic profiles.

2. **One output routing decision:** Add `BedrockOptions.StructuredOutputMode` (`auto` default, `outputFormat`, `jsonTool`) and parse only the relevant `anthropic` request options (`structuredOutputMode`, `disableParallelToolUse`) as an optional fallback; `amazonBedrock`/legacy `bedrock` selection remains complete-namespace precedence. In `auto`, native requires Anthropic identity, schema, the upstream reliable-native blacklist (including Sonnet 4.6/Haiku 4.5), and capability OR thinking OR explicit Anthropic family. `outputFormat` explicitly overrides the auto reliability gate for an Anthropic schema; `jsonTool` forcibly removes caller-provided `output_config.format` while retaining `effort` and other sibling fields, then uses the synthetic tool (including when user tools exist). Otherwise the newest models without strict support use the JSON instruction only when user tools exist and mode is not `jsonTool`. Reconcile pass-through merge so caller fields cannot reintroduce a removed format. Existing response metadata controls both generate and streaming JSON-tool conversion. Alternative: keep fixed model-gated fallback; misses user override and incorrect option precedence.

3. **Tool preparation:** Separate strict-tool support blacklist from reliable-native blacklist. If strict is `true`, recursively require `additionalProperties:false` on every object in all nested JSON Schema locations checked by pinned `isStrictToolSchemaCompatible`; boolean schema is valid. Unsupported strict (including explicit `false` on newest models) emits an unsupported warning and omits the field, never fails the request. Anthropic provider tools continue through `additionalModelRequestFields.tool_choice` and toolConfig definitions, with pinned unsupported web-tool filtering and required beta propagation; use pinned provider-tool schema catalog rather than trusting arbitrary caller input when supported. `anthropic.disableParallelToolUse` routes effective `tool_choice` with `disable_parallel_tool_use:true` through additional fields for function tools or Anthropic provider tools, omitting conflicting `toolConfig.toolChoice`; `none` drops function-only tools, but if supported Anthropic provider tools are present the pinned Bedrock preparation retains their definitions and any accompanying function tools in `toolConfig.tools` without a choice (including no parallel-disabling choice); tool-required betas remain. Forced JSON tool uses the effective required choice. Alternative: emit both choice locations; Bedrock can reject conflicting values.

4. **Wire fields and naming:** Match GPT-OSS using anchored optional regional prefix plus `openai.gpt-oss-` and flat `reasoning_effort`; other OpenAI IDs use nested `reasoning.effort`, preserving unrelated nested pass-through fields. Nonmatching substrings remain non-OpenAI. Apply upstream document name algorithm: strip extension, normalize whitespace to a space, remove characters outside ASCII letters/digits/space/`()[]-`, trim, cap at 200 and trim again; empty sanitized names fall back to a generated document name. Apply consistently to inline and tool-result documents. Preserve cache-point placement and explicit beta + tool-required beta ordering/precedence under `additionalModelRequestFields`; test override conflicts. Alternative: broad substring checks or unsanitized filenames risk wrong wire shape/validation errors.

5. **Dependency and proof boundary:** Prefer a private Bedrock strict-schema compatibility helper and existing published root `internal/anthropicschema.Sanitize`; the local provider-tool schema catalog was derived from `@ai-sdk/anthropic` 4.0.58 factories using `@ai-sdk/provider-utils` 5.0.45 and pinned `zod` 3.25.76. Regenerate from the registered versions when upgrading the baseline. If implementation needs a *new* root helper, publish producer before Bedrock consumer, update module pin/lock and prove `GOWORK=off` readonly resolution against the published version. Only real `mise run record-conformance` provider inputs or byte-identical registered upstream fixtures with INDEX provenance may enter provider conformance directories. Local request snapshots/HTTP fakes cover synthetic routing and failures but cannot establish live Bedrock acceptance; assess existing expectations before parity-check. Alternative: synthesize provider event fixtures, prohibited by provenance policy.

## Risks / Trade-offs

- [Explicit `outputFormat` may be rejected by Bedrock on newer models] → Match upstream's explicit override, retain failure visibility, test emitted request without claiming live support.
- [Profile without family/budget cannot be identified] → Require explicit family when available; preserve current unknown behavior otherwise.
- [Malformed `anthropic` options, conflicting pass-through fields or strict schema] → Return existing option decode errors; warn/drop unsupported strict; assert derived format/choice precedence with targeted tests.
- [Schema helper from unpublished root cannot resolve in published Bedrock module] → Keep helper local or publish-and-pin with standalone readonly consumer test before adoption.
- [Fake-transport evidence does not prove AWS accepts payloads] → Document coverage boundary; record via authorized live capture only when available.

## Migration Plan

Ship Bedrock module change with no baseline upgrade. Existing callers retain default `auto`; callers using formerly unrecognized profile IDs can opt into `WithModelFamily`, and callers relying on Sonnet 4.6/Haiku 4.5 native auto can explicitly choose `outputFormat` while accepting Bedrock-side risk. Revert Bedrock module version on regression; do not change root module unless a published producer helper is genuinely required.

## Open Questions

OpenSpec/owner approval of the proposed public `WithModelFamily` constructor API remains an implementation prerequisite; issue registration does not approve the constructor-versus-request-option choice. Its model-scoped rationale follows pinned upstream model settings and the existing Go `New(...Option)` pattern. Live Bedrock account-dependent acceptance of native mode and provider-tool beta combinations remains unproven without recorded credentials.
