## Context

The registered comparison is `@ai-sdk/anthropic` 4.0.58, upstream git object `08ae5ad05bc12496dd1ffcf64e34419e0831300d`. Its `anthropic-language-model.ts:getModelCapabilities` selects generic Sonnet/Opus 4 models with `/claude-(?:sonnet|opus)-4(?:-|@)/`; Go `providers/anthropic/models.go:getModelCapabilities` checks only `-`, leaving `claude-sonnet-4@20250514` and `claude-opus-4@20250514` on the unknown-Claude branch. `models_test.go:TestGetModelCapabilities_AllBranches` currently asserts that erroneous fallback. Direct `New` and Vertex `NewVertex` share `buildParamsWithCapabilities`; Vertex first calls `ResolveVertexModelID` in `model.go`. Capability selection controls default/clamped max tokens, reasoning, structured output, and sampling warnings.

Pinned `anthropic-prepare-tools.ts` and its tests define six web variants: search 20250305/20260209/20260318 and fetch 20250910/20260209/20260318. Go supports the older four in `convert_request.go:convertProviderTool`, but neither 20260318 variant. `tool_name_mapping.go:providerToolNames` supplies aliases for request tool choice, history and response mapping. `convert_request.go:validateProviderToolArgs` only validates advisor today; existing web conversion silently ignores malformed supported fields. `anthropic-sdk-go v1.61.0` already has typed beta request union members for both new tools with the required fields. Issue #204 was closed unmerged; its proposal is not a source of accepted behavior. The provider-adapter row in `test/conformance/PARITY.md` remains mixed; this is independently deliverable parity work, not a pin upgrade.

## Goals / Non-Goals

**Goals:**
- Select pinned capabilities for dated and undated Claude 4/5 direct and Vertex IDs while keeping the transport ID from `New`/`ResolveVertexModelID` untouched.
- Match pinned request type, projected fields, server-tool aliases, and beta-header rules for every supported web variant; fail malformed supported web arguments before HTTP for both `DoGenerate` and `DoStream`.
- Retain preexisting function-vs-server tool behavior (function `strict`, `inputExamples`, `ProviderOptions`, server args), no-tools choice behavior and warnings; prove with request-level tests.

**Non-Goals:** Public typed tool factories, changing the Vertex model catalog or arbitrary-ID acceptance, moving 20260209 dynamic-code-execution marking to other versions, caller-metadata fixes, new response/wire types, pin upgrades, or claiming provider-live validation from synthetic inputs.

## Decisions

1. **Change only capability classification, not transport IDs.** Amend the two generic `getModelCapabilities` Sonnet/Opus 4 checks to match `(?:-|@)` at that family boundary, after existing specific 4/5 and 5 branches. Keep the direct and Vertex model-ID resolution paths and unknown fallbacks unchanged. Test direct hyphen dates, bare/`-0` aliases, resolved Vertex `@` dates, 4.1/4.5/4.6/4.7/4.8 and 5-specific precedence, and unknown Claude/non-Claude inputs. Alternatives: rewriting `@` to `-` for lookup (risks conflating IDs) or changing the Vertex catalog (out of scope). Preserve `claude-sonnet-4` without delimiter as unknown, exactly as pinned upstream.

2. **Use existing provider-tool representation and SDK types.** Extend `convertProviderTool` with typed `OfWebSearchTool20260318` and `OfWebFetchTool20260318` branches. Search projects `maxUses`, `allowedDomains`, `blockedDomains`, `userLocation`, `responseInclusion`; fetch projects `maxUses`, domain lists, `citations`, `maxContentTokens`, `useCache`, `responseInclusion`. No new beta for either 20260318 tool; preserve fetch 20250910 `web-fetch-2025-09-10`, and 20260209 search/fetch `code-execution-web-tools-2026-02-09`. Add both mappings in `providerToolNames`; keep function tools on `OfTool`, including default eager streaming, strict/schema and input examples. The upstream request test explicitly checks custom 20260318 search mapping and absent beta (`anthropic-language-model.test.ts`), and `anthropic-prepare-tools.test.ts` checks both variants. Alternative: raw wire overrides, unnecessary because v1.61.0 supports all required fields.

3. **Validate supported web-tool args at shared request preflight, preserving numeric parity.** Extend `validateProviderToolArgs`, called inside `buildParamsWithCapabilities` before generate/stream HTTP, with schema checks for *declared* web IDs. Check optional fields' types, including non-null JSON values, lists of strings, present `citations` requiring boolean `enabled` and present `userLocation` requiring `type: "approximate"` with optional string fields, and `responseInclusion` enum (`full`/`excluded`) only for 20260318. Project only declared version-specific fields; follow upstream z.object's stripping of unknown keys rather than forwarding them or rejecting unknown fields. The pinned web schemas allow any finite `z.number()` for `maxUses`/`maxContentTokens`; SDK `v1.61.0` exposes `int64` tool fields. Use typed SDK fields for exactly representable integer values and `option.WithJSONSet("tools.<index>.max_uses" / "tools.<index>.max_content_tokens", number)` request options for upstream-valid fractions/out-of-int64 values. Derive final tool indexes from the converted request (skipping unsupported IDs and avoiding patches after `ToolChoiceNone` removes tools, including when a non-native JSON response format appends a synthetic function tool), so the same body reaches both generate and stream; verify with HTTP capture. A standalone fake-HTTP SDK probe using `Beta.Messages.New` plus `WithJSONSet("tools.0.max_uses", 1.5)` produced `"tools":[{"name":"web_fetch","type":"web_fetch_20260318","max_uses":1.5}]` on SDK v1.61.0. Alternatives: reject upstream-valid fractions (unapproved deviation), truncate silently, or upgrade the SDK/add a public API (unnecessary). Retain advisor validation, unsupported-tool warning/skip path and function `ProviderOptions`/`InputExamples` handling; do not interpret provider-tool function settings.

4. **Prove the request boundary without inventing live evidence.** Add table-driven direct/Vertex request tests in `models_test.go` and `convert_request_test.go`, capture generate and stream HTTP request bodies/`anthropic-beta` headers, verify tool choice with empty tool lists, custom aliases round-trip and function/server mixtures, supported/unsupported strict model handling, valid and malformed function input examples/provider options, and supported web argument invalid cases with zero HTTP calls. Compare expectations to the pinned TS source/tests and preserve existing controls; synthetic transport cases are focused tests, not provider recordings. Only real recorded provider events or byte-identical indexed pinned upstream fixtures may be added under provider conformance; if unavailable, document live-acceptance gap in review, not fabricated snapshots. The new 20260318 aliases change the tool names emitted in provider stream parts even though UI framing is unchanged. Add a deterministic provider-part scenario under `test/integration/testserver/` with custom search/fetch names and a matching Vitest test under `test/integration/` that parses SSE using `parseJsonEventStream`/`uiMessageChunkSchema`, asserts custom tool names on chunks, and verifies assembled messages with `readUIMessageStream`. Keep actual native-to-custom alias mapping covered in Anthropic provider generate/stream tests; synthetic provider parts prove frontend interoperability, not the native adapter. Run `mise run test-integration` alongside the Anthropic module tests and `mise run parity-check`.

## Risks / Trade-offs

- [Upstream Zod accepts fractional numbers but Go SDK request fields are `int64`] → Preserve finite fractional values via SDK request-option JSON overrides; prove on real serialized request bodies that overrides use the final converted tool index and never add a tool that `ToolChoiceNone` removed, even when the JSON-response fallback subsequently appends a function tool. Keep ordinary integers on typed fields.
- [Preflight rejection alters previously silently dropped malformed web fields] → Restrict failures to declared, supported web IDs; assert error before any HTTP request and preserve unknown-tool warning semantics.
- [Multiple beta sources or aliases are combined incorrectly] → Capture whole HTTP bodies/headers with mixed tools and explicit betas, including the no-beta 20260318 case and deprecated versions.
- [Synthetic requests are not live service acceptance] → Keep provider adapter coverage marked mixed; do not change stable `PARITY.md` status solely for this work.

## Migration Plan

No migration for callers using existing IDs or `New`/`NewVertex` signatures. Requests with invalid supported web arguments now return an error before HTTP instead of silently omitting fields; callers must correct the argument shapes. Roll back the change as a unit if request snapshots uncover incompatible SDK serialization; no schema/data migration or public dependency publication ordering change is planned.

## Open Questions

None blocking proposal. During implementation, verify Go SDK's exact marshaling of optional `use_cache: false`, `response_inclusion`, explicit zero and fractional/out-of-int64 numbers (including stream, skipped/removed-tool and JSON-fallback cases) with request capture, and whether any preexisting provider request fixture can legitimately exercise these variants. No live recording is available in this plan.
