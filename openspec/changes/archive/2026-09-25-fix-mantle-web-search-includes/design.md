## Goals / Non-Goals

**Goals:** Match pinned upstream default/explicit precedence for automatic web source inclusion; disable that automatic include only for Mantle Responses; prove the generated generate/stream request shape and independently consumable dependency chain.

**Non-Goals:** Block explicitly requested `include` entries or validate Mantle server support for such explicit values; change web tool dispatch, returned citations, unrelated include kinds, chat support, #207 assistant-history behavior, #164 reasoning-summary behavior, or the upstream pins.

## Decisions

1. Add a narrow default-true provider-adapter model capability for automatic web source inclusion, configured false only in Mantle's `NewResponses` construction (`providers/openai/model.go`, `options.go`, `providers/bedrock/mantle/provider.go`). Do not infer it from model IDs, provider identity, or general tool support: the upstream setting describes an endpoint feature, not model-family capability. Alternative: strip `include` in Mantle transport; rejected because it would remove caller-specified includes and obscure request behavior. The exported `WithWebSearchSourcesIncludeSupport(bool)` option was approved for this implementation; the model capability remains specific to endpoint support.
2. Add the approved tri-state `OpenAIResponsesOptions.IncludeWebSearchSources *bool` via typed provider options (`providers/openai/options.go`, resolved in `convert_request.go`). An unset value and true preserve OpenAI's auto-include; false disables auto-add even if model capability is true. A model capability false dominates an explicit per-call true. In `applyIncludeAndReasoning`, seed the include set from `popts.Include`, then conditionally auto-add sources on `hasWebSearchTool && capability && (perCall == nil || *perCall)`. Thus an explicit `include: ["web_search_call.action.sources"]` survives either disabling switch, matching upstream. No web tool means no automatic web sources regardless of switches. Alternative: use a plain bool or remove already seeded values; rejected because false would be indistinguishable from unset and explicit includes would be erased. Preserve automatic logprobs, code-interpreter outputs and stateless encrypted reasoning plus existing stable include ordering.
3. Capture focused OpenAI request bodies for the default, explicit true/false, capability true/false, absence of web tool and explicit `Include` combinations for `openai.web_search` and `openai.web_search_preview`; cover both `DoGenerate` and `DoStream` via shared builder or request capture. For Mantle, use a strict fake endpoint in `providers/bedrock/mantle/provider_test.go` that rejects requests containing the unsupported *automatic* web sources include and accepts correctly formed web-tool generate and SSE stream requests. Separately test that a caller's explicit source include remains in the serialized request (the strict endpoint may reject it; do not claim acceptance). Assert other include types and provider/tool attribution remain intact. This proves encoding only, not actual AWS behavior. Check existing conformance request snapshots for affected cases and regenerate expectations only if existing provenance-valid inputs require it; do not invent recorded or upstream provider fixture inputs.

## Risks / Trade-offs

- [Strict fake transport can show request encoding but not real Mantle acceptance or actual web-search results] → Label proof synthetic and leave live recording as a coverage gap unless genuine provider events are captured.
- [Consumer may silently use stale published OpenAI code] → Land and publish standalone OpenAI producer first, then update Bedrock's OpenAI module requirement and sum to that published version; run `GOWORK=off` readonly tests against published dependencies rather than relying on `go.work`.
- [Over-gating may remove explicit caller intent or unrelated includes] → Request matrix asserts explicit precedence, tool emission, code interpreter/logprobs/encrypted reasoning and no-web-tool behavior.

## Migration Plan

Implement and test OpenAI producer as an independently releasable change; publish it. Adopt that published producer in Bedrock's `go.mod`/`go.sum` before merging Mantle consumer change; verify each module standalone without workspace substitution, plus `mise run parity-check` for affected parity behavior. Roll back the Bedrock adoption to the previous published version if necessary; do not merge a Bedrock consumer referring to an unavailable version.
