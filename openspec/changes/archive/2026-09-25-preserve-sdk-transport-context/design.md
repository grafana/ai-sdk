## Context

The issue remains reproducible in Go: `providers/anthropic/model.go:107-126,136-157` ignores `params.Headers` and returns a stream without `Request`/`Response`; `providers/openai/model.go:82-105,141-160` already applies per-call headers but returns no successful transport metadata. `convert_response.go` in each module leaves unary request/HTTP headers empty. Both `consumeStream` paths omit `PartRaw`. `streamtext.go:1167-1175,1288-1296` copies `StreamResult.Request` but takes step response headers only from `PartResponseMeta` (neither SDK-backed adapter puts HTTP headers there). `provider/language_model.go` and `provider/stream_part.go` already define every required field.

Registered upstream: `test/conformance/upstream.yaml` pins commit `08ae5ad05bc12496dd1ffcf64e34419e0831300d`, Anthropic 4.0.58 and OpenAI 4.0.71. Their pinned language-model implementations and tests use call headers, request bodies, actual HTTP response headers, unary response bodies, and raw chunks before normalized events. `packages/provider-utils/src/parse-json.ts` assigns `rawValue: undefined` on syntactically invalid JSON but retains a parsed value on schema-validation failure. The Go official SDK versions are `anthropic-sdk-go@v1.61.0` and `openai-go/v3@v3.48.0`; the provider modules use these via `go.mod`, not the TypeScript transport. Existing `test/conformance/PARITY.md` states server-side captures cannot prove returned metadata.

## Goals / Non-Goals

**Goals:** Preserve transport observability inside the existing provider-result contract, correct Anthropic per-call headers, emit opt-in decoded raw events with defined error behavior, expose stream headers on core steps, and prove the provider boundary independently of conformance replay.

**Non-Goals:** Change public result types, SDK authentication/client construction, provider request-option conversion (#216), model capabilities (#220), logprobs (#31), Gateway raw-output policy (#116), or ProviderWire design (#80/#69); do not pass backend metadata into Gateway public normalization or change SSE framing.

## Decisions

1. **Use call-local SDK request options for headers and capture; do not replace clients.** Anthropic constructs direct or Vertex SDK clients and appends `br.requestOptions` and `m.requestOpts` for each call. Apply ordinary call headers after those options with `option.WithHeader`, using `http.Header.Set` for case-insensitive call override. `anthropic-beta` is the exception: pinned upstream `getBetasFromHeaders`/`getHeaders` (`anthropic-language-model.ts:938-969`, test `:8479-8506`) lowercases, trims, unions and deduplicates configured and call beta tokens. Do not overwrite the configured beta header with `WithHeader`: add a call-local middleware that reads the final configured/SDK-injected beta header and merges call tokens in upstream order without duplicates. The SDK adds `params.Betas` with `WithHeaderAdd` after supplied request options (`betamessage.go:95-106`); preserve these too. Test mixed-case ordinary header override, beta merging/deduplication, Agent marker and auth on direct/Vertex, unary/streaming calls; verify custom SDK middleware does not undo precedence. The OpenAI adapter already passes call headers via `requestOptions(params.Headers)`; preserve it. Keep SDK-controlled auth, retries, HTTP client, beta settings and `NewResponsesWithClient` unchanged. Do not silently change the SDK's treatment of reserved credential headers.

2. **Capture the SDK-submitted request body, not a guessed params marshal.** Add a call-local, innermost pass-through SDK `option.WithMiddleware` around the outgoing `req.Body`: a forwarding `io.ReadCloser` tees bytes as `next(req)`/the transport consumes them, forwards `Close`, and copies the complete captured bytes into `RequestMetadata.Body` only after a successful attempt. Do not call `req.GetBody()` to read its copy: installed Anthropic Vertex `vertex/vertex.go:139-145` rewinds and returns the *same* `bytes.Reader` used by `req.Body`, so reading the apparent copy before `next` drains the transmitted body. Also avoid using `GetBody` merely as a readiness test. The SDK retry loop (`requestconfig.go:435-472`) recreates a request for each attempt; keep separate per-attempt captures and retain only the successful returned attempt, including Vertex's final model/anthropic_version rewrite. Check read errors/completeness (known `ContentLength`), missing bodies and JSON validity; when the capture itself is incomplete or bypassed, omit the optional request body instead of inventing bytes. The captured body describes the bytes read from the SDK-created request. An arbitrary downstream caller-supplied transport may rewrite the body after that boundary without the adapter being able to detect it; such transports are outside the exact-wire guarantee. Normal configured clients and Vertex remain subject to endpoint byte-equality tests. This does not replace the HTTP client/authentication, buffer the streaming response, or mutate replay/close semantics. Compare captured request bytes with the HTTP endpoint's received bytes for direct, Vertex, OpenAI and configured clients (including a retry), in both modes; test the Vertex alias case explicitly.

3. **Use the actual SDK HTTP response headers.** OpenAI already captures `*http.Response` with `option.WithResponseInto` (unary) and `option.WithResponseBodyInto` (stream); reuse those values. Anthropic supports `option.WithResponseInto(&resp)` for both modes; append this to its per-call options, without overriding the stream's own `ResponseBodyInto` or reading its body. Copy header values into `map[string]string` using the upstream Fetch-style normalized header names/value joining, with no invented response metadata when there was no successful response. Preserve unary parsed IDs/model/timestamps and OpenAI's `RawJSON()` body; set Anthropic unary `Body` from the SDK message `RawJSON()`. Streaming `Response` contains *only* headers, not body; store copied headers by value before returning the stream. Do not stash raw `*http.Response` on a model or retain streaming response bytes.

4. **Raw events follow the pinned parse-result boundary, including failures.** Pinned `safeParseJSON` returns `rawValue: undefined` on syntax failure (`parse-json.ts:89-111`); both pinned provider transforms enqueue raw *before* handling failed parsing (`anthropic-language-model.ts:1740-1747`, `openai-responses-language-model.ts:1583-1603`). Existing Go `PartRaw.RawValue` is optional `json.RawMessage`: nil represents that undefined raw value without a new API. `stream-start` stays first; on `IncludeRawChunks=true` send one copied raw JSON part before normalized parts from each available valid event (including schema-invalid/unknown and error-envelope JSON), or a nil-valued raw part before the error from an observable syntax-invalid event. Omitted/false emit none. In OpenAI `stream_preflight.go:52-71`, carry owned `frame.Data` or a nil raw marker on each `responseStreamItem` through preflight so buffered events retain raw/normalized ordering; a parsed error envelope after stream acceptance emits its JSON raw part before `PartError`. An error rejected by initial preflight returns an error and no stream/raw parts. `[DONE]` and framing-only keepalives do not represent parsed events. The Anthropic SDK consumes `ping`, syntax failures and SSE `event: error` before `Stream.Current()` (`ssestream.go:189-216`). For opted-in raw output, append a call-local `option.WithMiddleware` that wraps only a successful SSE response body in a forwarding `io.ReadCloser`. The wrapper releases no more than one complete SSE frame per SDK read, forwards the original bytes and close to the SDK-owned decoder, and parses event `data:` only to enqueue the raw JSON value (or nil on invalid JSON). The adapter flushes frames observed during preflight only after acceptance, then emits frames read by subsequent `stream.Next()` calls before normalizing the SDK event or emitting its error. Frame-limited reads prevent `bufio.Scanner` read-ahead from moving future raw events ahead of earlier normalized parts. Do not register a global decoder, consume the body twice, replace the SDK client/authentication or bypass SDK error conversion. For a preflight error, close the stream and discard buffered raw. Only complete frames become raw parts; ignore `[DONE]` and framing-only comments. The installed SDK silently skips a malformed `ping` (and can skip unknown SSE event types), whereas the pinned upstream parser reports invalid JSON or schema errors. The wrapper still exposes a nil raw part for malformed JSON or parsed raw JSON for unknown frames but does not synthesize a `PartError` when the SDK reports none. This is an explicit limited-support boundary under #229, not full upstream error parity; synthesizing errors only in raw mode would change normalized output based on an observability option. Test LF/CRLF, multiline data, split reads, repeated/unknown frames, ping, malformed and SDK error frames, preflight, close and cancellation using the pinned upstream behavior. If a frame class cannot be delivered faithfully through this per-call wrapper, record the exact residual gap and seek an explicit upstream-sync disposition before claiming complete parity.

5. **Expose transport headers on core steps, but not Gateway output.** Initialize `responseHeaders` from `streamResult.Response` at `streamtext.go:832-833`; event-level non-nil `PartResponseMeta.ResponseHeaders` may supersede it without losing the fallback when an event carries only ID/model metadata. `step.Response.Headers`, `OnStepFinish`, `StreamTextResult.Response()`, and collected `GenerateText`/Agent results then inherit the headers. Do not serialize provider headers/body in `ai-gateway/providerwire/v4` success responses: its existing allowlisted normalization excludes them. `PartRaw` is provider/core observability; it is not new Gateway raw forwarding. The existing `streamtext.go` UI conversion maps `StreamRaw` to nil and does not serialize `Response.Headers` or `Request.Body` into `UIMessageChunk`; these changes therefore do not change frontend SSE chunk shape and do not require a new cross-language scenario. Test Gateway with a provider result containing secret headers/body/raw and assert all private fields remain absent.

6. **Cancellation must unblock every Anthropic stream send.** Follow OpenAI's bounded forwarding pattern (`providers/openai/convert_stream.go`): emit all converter and raw parts into a bounded internal channel, forward to the public stream with a `select` on delivery or `ctx.Done()`, and drain the internal channel after cancellation so no nested converter send can block. Check context before `stream.Next()` and before reporting a stream error; keep the SDK response body owned and closed exactly once by the producer goroutine's defer, including when the public 64-slot channel fills after a root consumer stops (`streamtext.go:906`). The forwarding goroutine closes the public stream only after the producer stops; it does not emit a cancellation-only error or finish. Deterministic tests cancel with a stalled consumer after >64 pending events, then assert prompt goroutine/body closure, no unread raw sends, and no extra error/finish parts.

7. **Conformance evidence stays provenance-safe.** Add targeted `httptest` or fake `RoundTripper` tests in each provider module for actual captured requests and returned result metadata, raw mode matrix (omitted/false/true), preflight/malformed/error frames, and cancellation/close. Add root core tests for step headers/request and response on `StreamText`, `GenerateText`, and Agent where these surfaces use the stream path. If a change affects frontend wire parts, add a deterministic `test/integration/testserver` scenario plus Vitest assertions using `parseJsonEventStream` and `uiMessageChunkSchema`, and run `mise run test-integration`. Do not synthesize `test/conformance/<provider>/recorded/input*.chunks.txt`; only regenerate existing snapshots if requests or externally observable parts actually change and run `mise run parity-check`. Update `PARITY.md` only if stable coverage evidence changes.

## Risks / Trade-offs

- **[Anthropic raw framing and SDK read-ahead]** → Test the call-local forwarding response wrapper against real SDK `NewStreaming`, including hidden frames, multiline/CRLF input, cancellation and resource ownership. Keep framing per call and opt-in. A malformed SDK-filtered ping yields a nil raw part without the parser error that pinned upstream emits; leave SDK error conversion unchanged and retain this bounded gap in #229 rather than implying full parity.
- **[Captured mutable response/request state or retry aliasing]** → Keep capture local to one call; copy header map and JSON bytes before returning; add overlapping-call and retry tests with the race detector.
- **[Streaming body ownership and cancellation]** → Capture headers only; leave one SDK/framing decoder in charge of the body, replace blocking Anthropic converter sends with context-aware delivery, and test cancellation with a stalled consumer and >64 pending events alongside early-error preflight.
- **[Private metadata leaks at the Gateway boundary]** → Preserve the existing allowlist, with explicit Gateway privacy regression tests, including raw and streaming metadata.
- **[Arbitrary client middleware transforms the request]** → Capture from SDK middleware as close to the HTTP request as SDK order permits, verify normal configured clients against deterministic HTTP capture, and define `Request.Body` as SDK-submitted bytes rather than final wire bytes for a downstream caller-supplied body-rewriting transport.

## Migration Plan

No schema or dependency migration. Implement in provider/core modules with their tests, then run the root/provider module suites, parity check, Gateway privacy tests, and cross-language integration only when wire behavior changes. Rollback consists of reverting provider/core edits without touching public result types or fixture provenance.

## Open Questions

No new public API is approved. Focused SDK tests must confirm configured middleware ordering and outbound byte identity for normal clients. A caller-supplied transport that rewrites after the capture boundary is outside the exact-wire guarantee; if capture at the SDK boundary itself fails, omit the optional field. The call-local response wrapper covers raw-frame order, preflight, cancellation and close. SDK-filtered malformed ping and unknown-event parser errors are an explicitly accepted limited-support boundary, tracked under #229, not an upstream-equivalence claim.
