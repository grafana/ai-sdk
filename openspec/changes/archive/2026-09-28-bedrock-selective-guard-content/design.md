## Goals / Non-Goals

**Goals:** Offer an explicit Bedrock-local typed API for selected user text and inline image parts; reject malformed recognized controls before network I/O; preserve default and false-part request shapes, existing namespace precedence and part ordering; cover unary and streaming requests plus authentic unary intervention finish/trace/usage.

**Non-Goals:** Change `provider.LanguageModel`/generic content shape; modify global `guardrailConfig`; add guard blocks to system/assistant/tool, documents, videos or S3 URL images; change Bedrock response conversion beyond fixes actually revealed by the authentic fixture; invent provider recordings; solve Gateway file/provider-option transport or expand live AWS coverage. No upstream baseline upgrade.

## Decisions

1. **Bedrock-specific proposed public part options, subject to owner approval.** Add `TextPartOptions{GuardContent *bool, GuardContentQualifiers *[]GuardContentQualifier}` and `ImagePartOptions{GuardContent *bool}` implementing `ProviderKey() string` returning `amazonBedrock` in `providers/bedrock/options.go`, alongside existing `FilePartOptions` (used for document citations). A named string `GuardContentQualifier` with `grounding_source`, `query`, and `guard_content` constants matches the upstream discriminator. The optional slice pointer distinguishes absent qualifiers from a caller-supplied empty array in round-tripped JSON. Usage is `provider.TextPart(...).ProviderOptions` or an inline `provider.FilePart(...).ProviderOptions`, not call-level `BedrockOptions`; no generic provider-contract change. Existing `FilePartOptions` remains untouched. Alternative: add guard fields to request-level `BedrockOptions` or `FilePartOptions` and apply to all files; loses per-text selection and conflates image with document configuration. The names/shape are a proposed API, **not** approval conferred by the issue; get owner/OpenSpec sign-off before implementation.

2. **Project per-part namespace options before validating part-specific controls.** `resolveBedrockOption[T]` (`provider_options.go:25-50`) rejects a different typed option occupying the same namespace (`provider.ResolveOption[T]` reports an unexpected type), so do **not** reuse it directly for part-specific text/image/citation reads. Add a narrow shared per-part reader in `provider_options.go` that checks `amazonBedrock` first, falls back to legacy `bedrock` only when the first namespace is absent/null (including a typed nil), and never merges the two. Read raw JSON directly; marshal a non-nil typed `provider.ProviderOption` to its JSON object and apply the same per-kind parsing/validation to that object. Reject malformed JSON, non-object selected namespaces and failed typed marshaling with contextual errors; treat a valid modern object with only unknown keys as present, so it suppresses legacy fallback. Check *only* recognized keys for the part being converted, ignoring other keys as the registered upstream per-kind Zod schemas do. This projection also applies to existing document-citation reads (`shouldEnableCitations`): a typed image/text guard option on a document must not become a citation type error, and a typed `FilePartOptions` on user text or inline image must not become a guard type error. Keep `resolveBedrockOption[T]` semantics for request-level/cache/reasoning callers unchanged, and preserve valid typed `FilePartOptions.Citations` on documents. Validate text's optional boolean and each qualifier's enum value and type, and inline image's optional boolean; wrong types, explicit null recognized control values, and unsupported text qualifiers return errors before network I/O. Distinguish absent keys from explicit null before unmarshalling into pointers, and validate typed enum values too. `false` or absent guard flag leaves text ordinary even with valid qualifiers, but still validates qualifiers. Image-only unknown qualifier properties are ignored; do not read image guard controls on documents, videos, URL images or tool-result images. Alternative: best-effort decode with defaulting silently drops malformed guard requests; directly calling the generic typed resolver rejects otherwise valid unrelated typed per-part options.

3. **One Converse content union member and shared request conversion.** Extend `contentBlock` (`api_types.go:64-75`) with `GuardContent *guardContentBlock` whose inner union is either `Text *guardContentText` (`text` always serialized even if empty, and optional `qualifiers`, preserving explicitly empty arrays) or `Image *imageBlock`. In `convertUserContent`, parse text part options before appending `{guardContent:{text:{text:...,qualifiers:[...]}}}` only if true; otherwise preserve `{text:...}`. For inline data images after existing media-type/source conversion, wrap `{image:{format,source}}` as `{guardContent:{image:{...}}}` only if true; preserve unguarded `{image:...}` and all other branches. Guard wrapping must not accidentally add a second content union key or modify source base64. `buildRequestWithFamily` remains common to both endpoints, and the no-option JSON is unchanged. Alternative: serialize guard blocks through top-level pass-through or duplicate endpoint conversion; neither preserves per-part semantics consistently.

4. **Authentic unary fixture with independent request proof.** Import `packages/amazon-bedrock/src/__fixtures__/amazon-bedrock-guard-content-intervened.json` byte-for-byte from registered `4e8c387...` as `test/conformance/bedrock/upstream/guard-content-intervened/input.response.json`, then map its exact upstream fixture name to that path in `INDEX.yaml`. The Go replay server already prefers `input.response.json` (`runner.go:756-806`); `runner.go:604-660` and `tools/common.mts:410-442` both carry text/file per-part provider options; `generate.mts:349-398` and `runner.go:1236-1287` support unary request/output snapshots. Supply `operation: generate` config with a guarded query text part and top-level trace-enabled guardrailConfig mirroring the registered upstream test; produce `expected-generate.json` and `expected-requests.jsonl` using the pinned tooling, then verify content-filter unified/raw `guardrail_intervened`, blocked input-assessment trace in `providerMetadata.bedrock`, input/output/cache and raw usage, and request shape. Keep captured response bytes untouched. Add focused Bedrock request conversion/HTTP tests for mixed guarded and ordinary text/inline images, all enum values and multiple/empty qualifiers, malformed controls and both namespace forms on both endpoints. No synthetic provider payloads in `recorded/` or `upstream/`. Alternative: claim the recorded streaming `guardrail` response fixture proves selective request wrapping; its request is ordinary text and cannot prove it.

## Risks / Trade-offs

- [A guard option accepted by typed Go but rejected by upstream validation, particularly null/enum] → Compare against the registered schema and assert focused wrong-type/null/unknown-enum cases for raw and invalid typed enum values.
- [Accidental protection of non-selected content, rejected unrelated typed options, or changed no-option JSON] → Exact request assertions on mixed prompts, false/unset, unrelated typed per-part options and unsupported file kinds for both endpoints; keep image URL handling unchanged.
- [Authenticated fixture proves response decoding, not live acceptance of guarded requests] → Keep upstream `input.response.json` byte-identical, pair it with pinned upstream/Go request snapshots and focused transport tests; only a separately authorized live recording can establish AWS acceptance.
- [Unrelated upstream usage fields or trace shape expose a previously missed decoder mismatch] → Address only fields needed by the authentic fixture, verify against upstream expected snapshots, do not rewrite fixture or infer extra behavior.

## Migration Plan

Additive Bedrock module release: existing callers without per-part options continue to send ordinary blocks; callers can opt in one part at a time. No data migration, root provider API change, pin update, or Gateway rollout. If a regression occurs, remove/revert Bedrock opt-in and its new conformance case without reinterpreting recorded inputs. Verify the Bedrock module independently with its own tests and registered parity checks before shipping.

## Open Questions

The proposed public Go `TextPartOptions`/`ImagePartOptions`/`GuardContentQualifier` names and optional pointer fields require owner/OpenSpec approval before coding; registration of #223 is not that approval. Live AWS acceptance of the selected guarded payload remains unproven without a separately recorded authorized run; neither fake transport nor upstream fixture alone establishes it.
