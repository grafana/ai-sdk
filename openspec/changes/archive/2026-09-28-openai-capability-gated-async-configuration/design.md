## Goals / Non-Goals

**Goals:** Align GPT-6 capability gates and warnings, request controls and ordering, async declaration and round-trip metadata, and the exact pinned programmatic execution-denial limitation. Test direct `DoGenerate` and `DoStream` and root generate/stream continuation where they consume provider metadata. Maintain default request semantics, omission versus explicit `false`, and immutability.

**Non-Goals:** New persistent async-job scheduler/polling API; changes to other providers or SSE chunk taxonomy; reasoning-summary suppression (#164); altering existing automatic compaction, sampling/Astra, approvals for ordinary direct calls, or claiming live provider acceptance based on fake captures.

## Decisions

1. **Model capabilities, not a hardcoded tool exception.** Add `supportsConfigurationUpdate`, `supportsAsyncToolCalling`, and a supported-efforts list to `modelCapabilities`, based on the existing anchored GPT-major parser; only `gpt-6` or later gets the new flags and `low, medium, high, xhigh, max` list. Non-GPT-6 efforts remain subject to existing behavior. Apply the list to the *resolved request effort* (provider option or core reasoning fallback) before it reaches `applyIncludeAndReasoning`; when unsupported, omit with the upstream unsupported warning. Avoid an unanchored prefix test or gating all reasoning models. Verify Mantle's `openai.` override and Azure namespace behavior separately rather than silently asserting identical endpoint support; gate any new Mantle flags on endpoint-owner verification. Baseline source: `openai-language-model-capabilities.ts:16-67`, `openai-responses-language-model.ts:311-327`.

2. **Approved typed options and request ordering.** Use a constrained `OpenAIReasoningEffortUpdate` option (allowed update values `low, medium, high, xhigh, max`), `*bool CompactionTrigger` on `OpenAIResponsesOptions`, `*bool Async` on `OpenAIToolOptions`, the custom provider tool args' `async` value, and `*bool Async` on `OpenAIPartOptions` for round-trip. The owner approved these Go names/types, constrained update-effort validation, tri-state booleans and namespaced metadata before implementation. Mantle's new GPT-6 flags remain disabled absent endpoint verification; the Azure identity uses the pinned OpenAI adapter's model capability lookup while retaining the `azure` metadata namespace. Use `ResponseConfigurationUpdateItemParam` as the first input item only for eligible GPT-6+ in standard reasoning mode, with no `ContextManagement` (including an explicitly present empty array) and no `Truncation == "auto"`; otherwise warn and leave the converted history intact. Insert `ResponseInputItemCompactionTriggerParam` last only when `compactionTrigger` is true, even for pre-GPT-6 (upstream has no model gate). Neither item becomes stored prompt history. Do not mutate `CallOptions.Prompt`, option slices, or reused models; build a fresh input slice with capacity before prepend/append. Alternate: raw JSON request body; unnecessary with the pinned SDK types. Baseline: `openai-responses-language-model.ts:417-445`, options schema :270-287,400-407 and tests :1868-1954,6390-6440.

3. **Async tool declaration and metadata use the existing provider transport.** At `prepare_tools.go`, write `async` on function, namespaced function and `openai.custom` only if explicitly set and supported; an explicit false is retained on any model; true on older models is omitted with an unsupported warning naming the tool. Do not alter `allowed_callers` or implicit parallel-tool semantics. Encode decoded `async` from function/custom generate outputs into `ProviderMetadata[providerOptionsName].async` only when JSON field is present (`v.JSON.Async.Valid()`), including false. For streamed function/custom items, retain field presence/value at `output_item.added` and use `output_item.done` value when present, otherwise the added value; avoid stale state across output indexes. Extend `OpenAIPartOptions` and assistant conversion to carry this metadata on non-stored reconstructed calls; stored provider-defined custom calls use item references where already supported; ordinary function calls stay inline even when stored, preserving `call_id`/output pairing (pinned `convert-to-openai-responses-input.ts:930-970`). Track provider options identity (`openai` vs `azure`) and verify existing `providerMetadataToOptions`/`ToResponseMessages` forwarding before changing root code. Alternative: a new provider contract field or SSE chunk type; existing provider metadata can carry this value without a wire-format change. Baseline: `openai-responses-language-model.ts:1098-1112,1918-1937,2043-2055`, `openai-responses-prepare-tools.ts:669-690`.

4. **Programmatic denial is a request-conversion boundary, not a new denial policy.** Pinned `convert-to-openai-responses-input.ts:1600-1624` throws for `execution-denied` *programmatic* tool results, identified either by result caller metadata or preceding assistant programmatic call ID; ordinary direct denied results convert normally, and synthetic provider-executed assistant denials remain omitted. Add the equivalent local error before constructing/sending a continuation request in `convert_provider_tool_continuation.go`/`convert_messages.go`, with a per-prompt call-ID lookup where result metadata was dropped. Preserve current provider-executed denial and approval handling. Root `streamtext.go` already has concurrent execution, approval requests, and synthetic execution-denied result projection; test both `GenerateText` and `StreamText` message assembly and only coordinate a core edit if tests show it drops required async/caller metadata. Alternative: globally reject all denied results or change approval semantics; both break existing behavior.

5. **Evidence and cross-module sequencing.** Test model matrix (including `gpt-5.6`, `gpt-6-astra`, `gpt-6`/later, malformed/third-party IDs and Mantle override), effort source/gates, warnings, true/false/absent async across function/namespaced/custom, conflict gates (`pro`, context management present even empty, auto truncation), trigger/update ordering with stored/un-stored history and previous-response ID, input immutability, generate/stream output metadata incl stream-added fallback, and programmatic vs direct denial. Use fake HTTP request captures and focused upstream-case tests, plus root tool-message continuation tests. Async metadata on `PartToolCall` propagates through `StreamToolInputAvailable` to frontend-visible `UIMessageChunk.ProviderMetadata` (`streamtext.go:1077-1092,328-341`), so add a deterministic `test/integration/testserver` scenario and matching Vitest test parsing with `parseJsonEventStream` and `uiMessageChunkSchema`. Assert `async: true`, explicitly present `async: false`, absence when unset, and assembled message/continuation metadata; do not introduce a new chunk taxonomy. The existing OpenAI `recorded/` and imported `upstream/` inputs contain no `async`, `configuration_update`, or `compaction_trigger` events or requests; `upstream/INDEX.yaml` does not list a matching case. No provenanced fixture can be extended by manufacturing provider events, so start with focused fake-HTTP tests and only add a new fixture after an approved live recording or byte-identical import from a pinned fixture. `PARITY.md` already classifies provider adapters and core/UI orchestration as mixed, and distinguishes request captures from returned metadata; no stable coverage status changes merely from this inventory. No hand-authored files under provider `recorded/` or `upstream/`. Run `mise run parity-check`, provider/root tests, candidate-source build/vet, and integration checks. Per PR #262's repository policy, an older merged OpenAI module pin need not compile candidate source and standalone public-proxy validation is not a source-PR gate; run it later as release evidence before separately publishing the provider module. No baseline change or upgrade PR is needed.

## Risks / Trade-offs

- [Explicitly empty context-management slice can disappear with `omitempty`] → preserve presence through the approved option representation or ensure a separate explicit-presence flag before gating; compare the pinned JS `!= null` behavior.
- [A Go SDK decoded boolean can be false when missing] → check SDK `JSON.Async.Valid()` on output and stream event items, store pointers only when present, test fallback and absence.
- [Downstream tools may lose caller metadata in synthesis] → test original and round-tripped messages in provider and root; do not skip programmatic denial when the result lacks caller but assistant call carries it.
- [Mantle and Azure may not support all OpenAI endpoint features] → test identity/capability override and preserve existing provider-owned boundaries; obtain endpoint-owner verification before enabling new flags for Mantle.
- [Fake transports are not live API evidence] → report the provider-boundary confidence gap in parity evidence; record via approved workflow if credentials are available, never fabricate inputs.

## Migration Plan

Additive typed options default to absent, so current callers retain requests except GPT-6 invalid effort strings now produce a warning and omitted effort. Approve public types first and validate coordinated root/provider behavior with required candidate-source checks. Regenerate any legitimate request expectations affected; standalone public-proxy validation remains provider release evidence rather than a source-merge prerequisite. Rollback removes the new opt-in controls and capability gates together; no persisted migration is required.
