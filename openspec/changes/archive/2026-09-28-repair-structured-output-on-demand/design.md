## Context

`test/conformance/upstream.yaml` pins `ai@7.0.109` at `4e8c387622ee1bb0d55841664416d38754d5c9a3` and records `structured-output-repair-text` as a core-orchestration gap. At that commit, `generate-object/parse-and-validate-object-result.ts` tries `repairText` on JSON parse/schema validation errors, passes original text and error, permits `null` to decline, and validates accepted repaired text once. Both legacy `generateObject` and `streamObject` pass the callback (their corresponding tests cover JSON parse and schema failures). The Go gap is real at current HEAD: `output/value.go:83-99` forwards options to `GenerateText`/`StreamText`; `streamtext.go:750-756` calls `Output.ParseComplete(step.Text)` at the final parse gate but stores failures directly, and `output/object.go:77-89` has no repair path. `PARITY.md` marks structured-output proof mixed. This is ordinary pinned-baseline implementation work, not a baseline upgrade.

The `aisdk.Output` interface (`output.go:18-31`) is implemented by the output package's Object, Array, Choice, JSON and Text strategies. `options.go:42-115,417-420` provides a `baseConfig` and shared `Option` applicable to both generation methods; wrappers accept these shared options through their existing variadics. The current `GenerateText` non-stop parse gate differs from `StreamText` (`parseOutputOnNonStop`), tracked separately by #226. `GenerateTextResult` and `StreamTextResult` keep raw text/content/usage independently of output value/error.

## Goals / Non-Goals

**Goals:** Opt-in single-attempt repair for complete structured output failure; a consistent option usable from direct `GenerateText`/`StreamText` and `output.GenerateObject`/`StreamObject`; preserve existing result shape, unchanged raw output and provider usage; retain inspectable causes of parse/validation errors.

**Non-Goals:** Changing the terminal parse gate (#226), introducing an extra model call, retrying provider/tool errors, repairing partial or element streams, editing UI chunks/SSE framing, modifying Gateway response-format handling (#114), adding upstream's deprecated `experimental_repairText` alias, or inventing recorded provider fixtures.

## Decisions

### 1. Share one operation option across wrappers and direct calls

Add `aisdk.RepairTextFunc` and `aisdk.WithRepairText(fn RepairTextFunc) Option` to root `options.go`/`output.go`. Callback shape: `func(text string, parseErr error) (repaired string, accepted bool, err error)`. `accepted == false && err == nil` declines repair and preserves the original validation error; `accepted == true` parses returned text, including empty text, as-is; a returned callback error takes precedence. The option only has an effect when `WithOutput` configures complete parsing. `baseConfig` carries the callback to `streamConfig` and `generateConfig.toStreamConfig`; wrappers require **no new signature** because their `opts ...aisdk.GenerateOption` / `opts ...aisdk.StreamOption` already accept `Option`. The callback belongs to one operation, not mutable output instances, so reusing an output across calls cannot leak callback state. Prefer this to `ObjectOption` (not supported by Choice and custom Output) or an output decorator (changes the parse interface behavior globally and introduces awkward wrapper-specific configuration).

The three-method `Output` interface remains unchanged, and any implementation conforming to it can participate. For builtin modes the same validation logic runs again: Object/Array/Choice/JSON; Text has no parse failure to trigger repair. `ErrNoObjectGenerated` is insufficient as the retry discriminator: `output/object.go:83-87` and `array.go:99-102` also use it when schema-valid JSON cannot unmarshal into the Go target type. Introduce a separate exported sentinel `aisdk.ErrInvalidOutputText`, meaning JSON syntax or schema validation of generated text failed. Builtin complete parsers wrap **both** sentinels only for their JSON syntax/schema-validation failures; typed conversion/unmarshal failures continue to wrap `ErrNoObjectGenerated` but not `ErrInvalidOutputText`. Custom `Output` implementations can opt in by wrapping both sentinels for repairable JSON/schema failures, without changing the `Output` interface. This additional marker avoids inferring failure stages from error messages or accidentally treating schema-valid generated text as repairable.

### 2. Repair only at the existing final parse gate and never recursively

At `streamtext.go:750-756`, call `cfg.output.ParseComplete(step.Text)` as now. Only when the error wraps **both** `ErrNoObjectGenerated` and `ErrInvalidOutputText` *and* the callback is non-nil, invoke it exactly once with `step.Text` and that same error. Do not repair schema-valid text rejected by Go typed unmarshaling (including custom `UnmarshalJSON` errors), even though existing behavior reports `ErrNoObjectGenerated` for those failures. On decline, keep that error unchanged; on callback error, store that error in `outputErr` (do not turn it into a stream/provider failure); on accepted repaired text, call **the same** `ParseComplete` once more and store its value or error, with no second callback. Valid first parse, nil output/option, non-validation error, aborted/missing stream, or steps for which complete parsing is ineligible never call repair. Existing final-step semantics remain untouched; no retry creates new provider usage. The callback receives the `ParseComplete` error rather than upstream's bare `JSONParseError`/`TypeValidationError`: this is a parity-preserving Go adaptation because Go's public `Output.ParseComplete` returns an error with `ErrNoObjectGenerated` identity, plus the new repairability marker, and the cause remains available via `errors.As`/`errors.Is` (next decision). An accepted but invalid repair returns the repaired parse/validation error, not the original one.

Unlike upstream legacy APIs which reject with `NoObjectGeneratedError`, this Go SDK already reports validation failures through `OutputError`/typed `Object()` or `Value[T]` accessors; use those existing result channels for every failure. The synchronous callback runs on the streaming worker at final parsing, so a slow callback delays completion; callers own its execution time and can respect their operation context if needed.

### 3. Preserve underlying error identity and raw response

Existing `output/object.go`, `array.go`, `choice.go`, and `json.go` wrap `ErrNoObjectGenerated` but interpolate underlying errors with `%v`; use Go multi-wrap (`%w`) for underlying parse/schema/unmarshal errors while retaining `errors.Is(err, ErrNoObjectGenerated)` and diagnostic context (not necessarily byte-for-byte error strings when the new marker is present). Wrap `ErrInvalidOutputText` alongside `ErrNoObjectGenerated` **only** on the JSON syntax/schema-validation branch, never on the typed unmarshaling branch. This lets callers inspect JSON syntax errors (`encoding/json`) and schema errors (`santhosh-tekuri/jsonschema/v6`) from the callback without depending on upstream TS error classes. Do not change the `schema` public API. Preserve original accumulated `step.Text`, `result.Text`, `Content`, `Steps`, `Response`, `Usage`/`TotalUsage`, `FullStream`/`ToUIMessageStream` chunks, and partial/element streams. Repair changes only `OutputValue`/`OutputError` or the typed `Object()`/`Value[T]` result. In particular, a repaired value is *not* silently substituted into model text or UI chunks.

## Risks / Trade-offs

- [Marker adoption] Existing custom `Output` implementations that wrap only `ErrNoObjectGenerated` keep their current failure behavior even when callers configure repair; repair is opt-in for custom outputs by wrapping the additional `ErrInvalidOutputText` marker for JSON/schema failures. Tests MUST verify single-sentinel and unrelated failures do not invoke repair. Do not infer applicability from arbitrary error text or re-run non-validation failures.
- [Callback may block] Callback is synchronous at stream completion; users are responsible for finite work and must not rely on it as a provider retry. No extra goroutine/cancellation abstraction is added.
- [Error wrapping changes inspectability] Existing diagnostic context and `errors.Is(..., ErrNoObjectGenerated)` stay intact, but the added marker may change exact error strings; `%w` additionally enables `errors.As` to find underlying causes and `errors.Is(..., ErrInvalidOutputText)` to distinguish repairable failures. Tests verify all three, including a schema-valid typed-conversion failure without the new marker.
- [Frontend effect mistaken for repaired model text] Unit tests compare raw text/stream parts/UI chunks, usage and repaired value. Since no UI chunk is modified, a new frontend/wire fixture is not required; if implementation changes chunks, add provider-independent `test/conformance/ui/` and schema-parsed `test/integration/` scenario before merge and run parity/integration checks.

## Migration Plan

Additive option; existing calls without it keep behavior. No persistence or wire migration; rollback removes the option and helper without affecting saved provider transcripts. No provider-module dependency or publication-order changes (root module owns implementation).

## Open Questions

None. Callback return semantics intentionally model upstream `null` with an explicit Go boolean; exposing upstream's deprecated alias is outside the issue.
