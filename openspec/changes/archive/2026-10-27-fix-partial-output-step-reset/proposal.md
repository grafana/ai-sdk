# Proposal

## Why

Reviewing #526 and the code around it found four partial-output and step-text differences from the registered `ai@7.0.143`:

- `streamText` compares each partial with the last one published in any step. Upstream's `resetOutputState()` clears that comparison on every `start-step`. When a later step's first partial equals the previous step's last one, Go drops it from `PartialOutputStream()` and holds back that step's text-delta until `text-end`, so the UI text-delta boundaries differ from upstream.
- `output.Array` returns a nil slice when the partial has no valid elements yet, which marshals to `null`. Upstream's `parsePartialOutput` returns `[]`.
- Partials parse the text of every text part in the step, in delta arrival order. Upstream parses only the first text part, chosen by the first text event of any kind, including `text-start`. Go chose the first part to send a delta.
- `StepResult.Text` joins deltas in arrival order. Upstream joins each text part's whole text in the order the parts started, which is also what the final output is parsed from.

The last two only show when one step streams more than one text part.

## What Changes

- Reset the published-partial comparison when each step starts.
- Return an empty, non-nil slice from the array `ParsePartial`.
- Choose the output text part at its first text event and parse only its text.
- Build step text from whole text parts in first-appearance order. A delta for a part that never started keeps its existing tolerant handling and joins at its first appearance.
- Add the provider-independent fixture `test/conformance/ui/partial-output`, generated by the registered upstream `streamText`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `structured-output`: partials parse only the first text part, are compared within a step, and an array partial with no valid elements is `[]`.
- `stream-text-lifecycle`: step text joins whole text parts in first-appearance order.

## Impact

Root module `streamtext.go` and `output/array.go`, and `GenerateText`, which runs on `StreamText`. `PartialOutputStream()` can now repeat a snapshot across steps, a step's first structured-output text-delta arrives as soon as it parses, and `Text()` changes only for steps whose text parts interleave or start before their deltas. No API change.
