## Context

`go.gateway.work` already selects exactly Gateway, root SDK, five providers and four middleware modules for source CI; root `go.work` intentionally excludes Gateway. `ai-gateway/Dockerfile` currently builds with `GOWORK=off` from `ai-gateway/` context using pinned (potentially older) published Go modules. The existing `image-validation` job gates images on standalone Gateway compilation; its license inventory drops workspace modules because they lack `.Version`. This deliberately supersedes the container portion of #258/#262, not the merged-pin or standalone SDK release safeguards. This is build/release infrastructure, not an upstream AI SDK API or protocol change; registered `test/conformance/upstream.yaml` versions (including ai 7.0.109 and @ai-sdk/gateway 4.0.88) and PARITY.md remain unchanged.

## Goals / Non-Goals

**Goals:** One explicit source-selection recipe for local, main SHA and Gateway-version-tag images; exact commit attribution and clean checked-out source for CI; amd64/arm64 and native smoke; accurate command/platform closure and first-party/external licensing; retained fail-closed gates and standalone module release checks.

**Non-Goals:** Publishing Gateway as a supported standalone Go module, floating module updates, new release coordinator or duplicated full CI fixture, SDK API/parity changes, release-please implementation, #245/#21 SDK release automation, digest promotion, module consolidation, licensing relaxation or ruleset changes.

## Decisions

1. **Root context with narrow inclusion and explicit workspace.** Invoke the same `-f ai-gateway/Dockerfile .` context for mise local build, buildx platform validation and buildx publication. Introduce root `.dockerignore` as an explicit allowlist for `go.gateway.work`, `go.gateway.work.sum` if present, selected module manifests/sums and command dependency source/embedded assets, plus root Apache and Gateway AGPL/notice files; explicitly deny `.git`, credentials, local config, node_modules, test fixtures and build artifacts. Do not rely on `ai-gateway/.dockerignore` when context is `.`. In the builder set `GOWORK` to the copied `/src/go.gateway.work`, use `-mod=readonly`, select platform with `GOOS/GOARCH` for build and inventory, and copy only the binary and required license evidence to the existing nonroot runtime. Check `go.gateway.work` selection matches source CI and ensure inputs for `go:embed` are included. Alternative: copy all repository files and blacklist a few paths; rejected because sensitive files could leak into layers/context. Root `go.work` remains SDK-only, never an implicit build selector. External versions/checksums, Docker image digests and Go tooling stay pinned; do not run `go get` or `go work sync` in Docker.

2. **Artifact-specific release gates.** Reuse `image-validation` and `publish-ai-gateway-image` on guarded main/tag pushes; remove `MODULE=ai-gateway mise run verify-published-module` as an image prerequisite, not the standalone command itself. Before builds, local, validation and publisher invocations SHALL verify that every Docker-relevant input selected by the root-context allowlist, plus the Dockerfile and context-selection/build policy files, is tracked and byte-for-byte identical to the selected commit; reject modified/deleted tracked inputs and admitted untracked inputs (including Git-ignored files). CI additionally verifies `git rev-parse HEAD == GITHUB_SHA` in both jobs with checkout credentials disabled. Perform this check before passing that verified commit as `VCS_REF` for both OCI label and inventory; local builds also require clean included inputs and use the verified HEAD SHA, rather than attributing dirty bytes to HEAD. The selected allowlist and verification must cover the same inputs actually sent to Docker, not merely `git status` without ignored/untracked entries. Do not pull ambient workspaces or module replacements. Retain required source checks, pin ancestry, source-absence and boundary policy checks, buildx amd64/arm64 OCI validation, native image readiness smoke and publication's dependency on successful validation; deployment still needs successful publication and applies only to main. A tag selects checkout revision and image tag only, not a different recipe. Alternative: wait for SDK tags/repins to pass Gateway standalone; rejected because this recreates source-vs-production drift. Optional Gateway standalone diagnostics remain on demand; SDK/provider/middleware standalone checks remain the release boundary under #245/#21. Release-please still controls Gateway app version/changelog/tag, not standalone module support.

3. **License inventory from the built command.** Run `go list -deps` for `./ai-gateway/cmd/grafana-ai-gateway` with the same explicit workspace, readonly flags, `GOOS` and `GOARCH` as `go build`. Deduplicate module metadata for packages in that closure (not `go list -m all`); distinguish local workspace modules by module path/dir and record the build SHA for each, independent of `.Version`. Record resolved module version and sum for downloaded external dependencies from Go's metadata/verified checksums. Include applicable local Apache root LICENSE (nested SDK modules inherit it), Gateway AGPL LICENSE and its NOTICE, and existing discovered external LICENSE/LICENCE/NOTICE files. Ensure inventory and OCI revision label use the source SHA; maintain existing license boundary. Alternative: keep `.Version`-only output; rejected as it silently omits local source. Do not claim a new SBOM format or upstream/provider recordings.

4. **Focused regression, not duplicated CI.** Extend `test/conformance/tools/ci-workflow.test.mts` to check the selected context/Dockerfile/workspace and push guard/dependency/fail-closed invariants rather than incidental step order. Add one credential-free Docker fixture/test in an isolated worktree: commit the changed local SDK/provider behavior without changing the older merged pins, build with the actual local image recipe at that fixture commit, and observe the changed behavior in the image (and an optional standalone failure control). Assert the fixture commit SHA in both OCI label and local-module inventory and validate readonly manifests, Apache/AGPL material and external versions. Also assert a modified included tracked file and an admitted untracked file each fail pre-build even when HEAD matches the supplied SHA; include an ignored-but-admitted file case if the allowlist can admit one. Use fake/mock endpoints, never real credentials or invented recorded conformance chunks. Cover both main and version-tag paths through existing workflow recipe assertions, not a second full GitHub CI simulation. Run relevant module-policy/workflow tests and real native/multiarch build/smoke as available, clearly recording Docker availability.

## Risks / Trade-offs

- [Broader root context leaks secrets or misses embedded assets] → Default-deny allowlist plus sentinel/context inspection test and image-layer checks; explicitly include only required command inputs and licenses.
- [Workspace changes while hashes/pins remain stale] → `-mod=readonly`, pinned external resolutions, no build-time manifest edits; tests verify SHA and effective local behavior, not merely `go list` paths.
- [Cross-architecture license inventory drifts from built binary] → inventory and build use the same target `GOOS/GOARCH`, explicit workspace and command; test both target platforms.
- [No Git metadata inside Docker due to context hygiene] → pass the SHA only after caller-side verification of the actual included Docker inputs against the selected commit; local dirty included inputs fail rather than receive a false clean SHA. CI requires HEAD to equal the event SHA and also rejects modified or admitted untracked/ignored included inputs. Excluded ambient artifacts remain outside the context.
- [Gateway `ai-gateway/vX.Y.Z` Go tags remain discoverable] → document unsupported Gateway standalone consumer contract; #245/#21 own Go module release readiness.

## Migration Plan

Land Docker context/recipe, workflow/test and spec/docs changes together so source CI and image checks cannot exercise different policies. Validate with OpenSpec, module-policy and focused tests, image platforms and native smoke before main publication. Existing tags remain immutable; new main SHA or Gateway release-tag pushes use their checkout SHA. Roll back via a revert of the coordinated policy change if image validation fails; do not silently switch back to older module pins or publish/deploy despite failure.

## Open Questions

No product decision is required for this proposal. During implementation inspect the command's complete embed/runtime inputs and whether the local Docker builder supports architecture validation; report unavailable buildx capability rather than claiming unexecuted proof. The externally visible inventory layout may retain the existing `THIRD_PARTY_MODULES.txt` filename for compatibility while clearly identifying first-party entries; decide its precise presentation when implementing without changing the license-evidence contract.
