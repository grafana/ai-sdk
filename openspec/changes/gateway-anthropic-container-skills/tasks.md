## 4. WP4: Aggregate chain-failure classification (design D10)

Paths are relative to `ai-gateway/`.

- [ ] 4.1 Add failing cases to `internal/execution/classify_test.go` `TestClassifyProvider` (L68), built in the shapes `fallback/fallback.go` produces (design D10): a single failure unwrapped (L319-321); several failures as a newest-first `errors.Join(wrap(newest), ..., wrap(oldest))`, where `wrap` is the `fallback: provider %q model %q: %w` wrapper (L322-328); and the call-level `ctx.Err()` as the last element of a further top-level join (L118, L146). "Refusal" means `catalog.ErrUnsupportedRequest` unless a row names `provider.ErrUnsupportedFunctionality`. Lists below are newest first.
  - `ErrUnsupportedRequest` rows:
    - `[503, refusal]` (refusal then 503) → overload; `[refusal, 503]` (503 then refusal) → overload; `[429, refusal]` → rate limit;
    - `[503, refusal, 429]` → overload (the most recent non-refusal decides);
    - `[unknown error, refusal]` → internal;
    - `[refusal, refusal]` → invalid request; a single refusal → invalid request (unchanged).
  - Call-level context rows:
    - `errors.Join(refusal, context.Canceled)` → cancellation; `errors.Join(refusal, context.DeadlineExceeded)` → timeout (one failure, then the call ends);
    - `errors.Join(errors.Join(wrap(503), wrap(refusal)), context.Canceled)` → cancellation.
  - No-refusal rows (the visible change in design D10 Scope):
    - `[503, wrap(context.DeadlineExceeded)]` (an attempt-level deadline, then a newer 503) → overload; today `classify.go:118-119` returns timeout;
    - `[503, wrap(context.Canceled)]` → overload, because an attempt that wraps `context.Canceled` is not call-level; today it is cancellation.
  - `ErrUnsupportedFunctionality` rows:
    - `[503, functionality refusal]` and `[functionality refusal, 503]` → overload;
    - `[unknown error, functionality refusal]` and `[functionality refusal, unknown error]` → internal;
    - `[functionality refusal, ErrUnsupportedRequest refusal]` → invalid request;
    - `errors.Join(functionality refusal, context.Canceled)` → cancellation;
    - `[ErrUnsupportedRequest refusal, 400 API error wrapping ErrUnsupportedFunctionality]` → failed dependency, because an API error that wraps the sentinel is not a refusal.
