## Goals / Non-Goals

**Goals:** preserve supported authorized caller semantics; classify every existing restriction; make disclosure provenance and bounds testable; preserve independently implemented Apache client/AGPL server delivery; prove both client boundaries with exact pins and authentic replay.

**Non-Goals:** BYOK provisioning/storage/credential selection, native API adapters, new provider-tool/generated-file/custom/approval/structured/raw capabilities, effectful fallback, public backend topology, baseline upgrades, changing core `PartError` termination, automatic client replay or exactly-once generation. Existing completed milestone criteria and archived changes remain historical.

### 2. Metadata is integrated once, under #280

#280 alone implements metadata preservation across supported unary result/content, stream text/reasoning/tool/source parts and finish, plus independent Go filters and real subsequent-request continuation. #303 supplies revised restrictions and integrates/tests its warnings/sources/identity/error packages against that delivered contract. No second metadata helper, allowlist, fixture owner or raw-chunk gate belongs to #303.

Registered metadata is `Record<string, JSONObject>` (`shared-v4-provider-metadata.ts`). Unknown namespaces/keys and nested null/false/zero/empty strings/objects/arrays are preserved in meaning, as are absent versus explicit empty outer objects. Top-level or namespace null is not a registered object; tests must distinguish rejection/normalization allowed by the pinned contract from nested null, not promise universal null passthrough. Existing reasoning latest non-nullish object replacement remains, rather than deep merge. #280 must freeze reviewed aggregate JSON/input budgets at each containing unary/event bound before dependent code ships; those budgets apply to all namespaces, not just known names. Original byte preflight, UTF-8/JSON validation, complete DTO/frame accounting and bounded copies are mandatory. Existing `usage.raw` remains independent.

This proposal revises contradictory reasoning/tool/source requirements to the integrated target; it does not authorize taking #280 implementation ownership. Metadata-dependent behavior packages land after #280 (or contain only independently green non-metadata work). No red cumulative stack or weakened tests.

### 3. Warnings, source display and actual identity

Warnings use exactly the registered union: unsupported/compatibility feature plus optional details; deprecated setting/message; other message. Preserve required empty strings and order; omit inactive fields. Current Go string fields cannot distinguish absent optional details from empty: normalize optional empty details consistently and document/test that Go adaptation. Unary warnings emit a non-null array; stream emits exactly one initial start with warnings; no warnings on finish. Cap each warning string at 4096 UTF-8 bytes, preflight count and aggregate bytes against the containing response/frame, then check full escaped encoding. Invalid/oversized output fails safely, not silently dropped or truncated.

Source URL/document unions and Title-before-legacy-Text behavior remain. Preserve original source ID, URL, title and filename, including OpenAI/Azure file_path display, without `source-N`, hashing, `Document` substitution or synthesized citation. No URL fetching/canonicalization. Optional empty URL title/filename normalization remains; required empty document title survives. Preserve duplicates/order as provider emitted them, including equal IDs across source variants; do not invent uniqueness by renaming. Metadata is #280's ordinary contract. Existing 1024-byte ID limit stays; aggregate strings and metadata fit the whole unary/event bound.

Requested alias and canonical route remain distinct from actual response identity. Logical model `Provider()`/`ModelID()` and discovery remain grafana/public route; observers ignore actual response fields. Stream `response-metadata` preserves optional provider id/modelId/timestamp exactly where represented, without canonical substitution or fabricating absent modelId. No new provider instance/topology field. Unary emits supported provider id/modelId/timestamp under registered `response`, excluding native headers/body. **Pinned TS overwrites typed unary response entirely**, and Go deliberately matches it: native identity is available in bounded raw `response.body` only, not typed `ResponseInfo`. Explicitly document/test this support boundary; a future typed unary fix requires separate upstream-client/API work, not a second dialect here. Useful actual provider identity in ordinary #280 metadata is retained, but not invented as an extra field.

### 4. Actionable provider errors use reviewed sources, not generic serialization

Keep `WriteError` host auth/permission/internal categories and Gateway protocol/resolver/panic/lifecycle errors fixed. Distinguish a provider API envelope from transport/internal errors; do not serialize `error.Error()`, `APICallError.Message`, URLs, headers, request bodies, causes or whole `Data`/`ResponseBody`. The latter are input to a bounded **selected-adapter** extractor, not automatically public diagnostics.

Initial reviewed sources (all extracted after byte/UTF-8/JSON checks):

| Adapter/source | Recognized schema and allowed fields | Exclusions/gaps |
|---|---|---|
| OpenAI/Azure HTTP (`wrap_api_error.go:59-85`) | inner error object or `{error: object}`; string message/type; string/finite-number/null/absent code; string/null/absent param | No unknown siblings or nested request/transport. |
| OpenAI Responses SSE (`stream_preflight.go`, `stream_adapter.go:250-264`) | documented error event or response.failed error object, same scalar fields after producer provenance review | Message-only fallbacks and local conversion/transport errors have no safe structured source and remain fixed. |
| Anthropic HTTP/SSE (`wrap_api_error.go:40-50,69-85,97-113`) | `{type:"error",error:{type:string,message:string}}` or documented initial-stream inner error; extract type/message only | Never `apiErr.Error()`; no generic envelope sibling details. Initial-stream 500/529 mapping retains existing producer semantics. |
| OpenAI-compatible (`errors.go:12-31`) | typed inner `Data` or `{error:{message,type,code,param}}` with same reviewed scalar fields | Operator-selected compatible endpoints need schema/provenance review; unknown envelopes get fixed safe fallback. |
| Other/missing structured sources | No passthrough; fixed actionable category/status fallback | Bedrock command composition is absent; producer representation gaps are separately registered/coordinated with #299. |

#### Trusted per-candidate provenance seam

`catalog.ResolvedModel` currently carries only ID/model/options (`catalog/catalog.go:29-37`), the logical factory replaces `Provider()` with grafana (`service/catalog.go:155-165`), and exhausted fallback joins failures newest-first (`fallback/fallback.go:290-303`). Neither logical identity nor an aggregate-wide `errors.As`/`errors.Is` pair can select an extractor safely. Keep those catalog/provider contracts unchanged and add an **AGPL-only internal `ai-gateway/internal/providererrors` package** shared by command composition and the V4 adapter, never by Apache providers/clients. It owns the reviewed adapter enum, private adapter sentinels, candidate model wrapper and projection selection. The zero/unreviewed adapter has no native-diagnostic authority.

In `service/catalog.go`'s trusted `providerConfig.Type` switch, wrap each constructed physical candidate with its reviewed adapter policy **before** appending it to `candidates`, constructing `fallback.New` or calling the logical factory. Preserve the lower model's identity for private attempt observation; this wrapper is not another logical middleware/telemetry chain. Do not derive policy from caller namespaces, public `Model.Provider()`, provider-instance names, error JSON types or the winning route's primary. Generic resolvers without the wrapper retain fixed safe diagnostics; they need no new `ResolvedModel` field, and their model execution is unchanged.

For non-nil `DoGenerate` and `DoStream` setup errors, the wrapper returns standard `errors.Join(privateAdapterSentinel, originalError)`. This two-child node is the in-process provenance boundary: the first child must be the exact private sentinel and the second is the original error for that same invocation. It adds no custom error type, provider/core field, credential/configuration identifier or public wire member. Do not call or serialize aggregate `Error()` prose. Wrapping rather than converting the original API error preserves `errors.As`/`errors.Is`, native retry overrides, context-window message/Data recognition and fallback decision rules. Result-plus-error, nil results, panic recovery and cancellation remain governed by their existing owners, not reclassified as provider envelopes.

For a streaming `PartError`, whose APICallError field is a concrete pointer, copy the part and create a new APICallError using existing `provider.NewAPICallError`: retain all original exported values and the exact IsRetryable override, and set Cause to the same sentinel/original two-child join. Projection reads only the paired original error, not unrelated errors in its cause tree. Never mutate a provider-owned part, API error, map or JSON bytes, or put provenance in Data/providerMetadata. Nil error pointers remain nil and fixed-safe. Other parts and result/request/response values pass through unchanged. One bounded context-aware forwarding goroutine per exposed source channel owns reads and bounded cancellation drain of that **input**; its output is owned by the existing fallback/handler reader. Wrap any non-nil result stream even with a setup error so existing result-plus-error cleanup still consumes the wrapper output. Never let wrapper and caller drain the same channel, spawn a goroutine per error, synthesize parts, pre-read beyond normal forwarding, or change first-part commitment. Test blocked delivery, abandoned providers and closure/cancellation for this added ownership boundary.

Projection traverses wrappers structurally with a bounded depth/node budget, rejecting malformed/cyclic/over-budget provenance to fixed-safe output. Recognize the exact two-child sentinel node before treating a multi-error as an aggregate; select its paired original API error only within that node's original-error subtree. For an exhausted fallback aggregate, first preserve context cancellation/deadline priority, then take the **first candidate-failure branch in existing newest-first order** and project that branch alone. If that authoritative branch has no reviewed provenance/API source (including nil-result, panic or premature EOF), use its fixed safe classification; do not search older candidates for nicer details. Never find one marker in a later branch and an API error in another, combine diagnostics across candidates, or enumerate the joined failures publicly. The same rule applies to direct errors and stream clones, where the clone's cause binds the same original. Native source schema/bounds and auth-prose safeguards below remain mandatory even with valid provenance.

Focused tests must cover direct unary/setup/PartError annotation; unconfigured resolver and zero policy; two candidates with different envelope schemas and shared/reused API error pointers; newest tagged/unreviewed/non-API failure; reversed marker/API branches and malformed provenance; cancellation joined with failures; errors.As/Is and context-window/native-retry decisions; first/later stream error commitment; and no candidate topology/markers in wire or telemetry. This is a server-only Go adaptation, not an upstream error-format extension.

Avoid changing provider/core error types just to make this projection convenient. #299 targets ai 7.0.116, not this reference; any required producer enrichment is a separately scoped, independently green coordinated package with published adoption proof.

Budget: structured source at most 16384 original bytes before parsing; message at most 4096 UTF-8 bytes; native type and string code at most 256 each; projected param at most 4096 encoded bytes; complete public error at most 16384 and within configured client/error or complete SSE budget. Code numbers must be finite JavaScript-safe numbers. Never truncate semantics to fit; invalid/over-limit detail uses fixed prose/code/null detail while retaining a valid status-derived category and retry behavior. Invalid HTTP status reduces to internal safe failure. Do not copy arbitrary nested `details`; initial supported details are native type, original status, and reviewed native scalar param.

Use the existing registered error members: message, Gateway-category type, native code (null when absent), param. For provider failures param is the documented closed object `{providerType?: string, providerStatusCode: integer, providerParam?: string | null}`; optional absent native param stays absent, explicit null stays null. No provider names/endpoints/account identifiers, raw error bodies, new root error fields or native transport. This is a bounded projection into registered unknown-valued param, not a second protocol. TS directly exposes message/status/class, and code/param are inspectable only through its bounded cause/data/body, not typed public code/details properties. Go preserves code/param through its public error and bounded APICallError representation. Change `GatewayError.Code` from string to `json.RawMessage` and add `Param json.RawMessage` for the registered projection; null is retained as JSON null, numeric codes remain numbers, and missing native codes normalize to null on the strict server. This is an explicit client API change, not silently stringified numeric codes; update call sites/godoc/release notes and legacy fixed-envelope tests together.

For provider credential/auth failures (native 401/403 or recognized authentication/permission types), use fixed actionable prose `provider account authorization failed` and omit arbitrary native message/param, retaining reviewed code/type/status only. These envelopes can echo authorization material. Never classify them as Gateway authentication (TS replaces authentication prose with Gateway-key guidance). For other reviewed provider messages, application strings are not regex-redacted just for looking secret. Adapter review must demonstrate that selected fields do not incorporate SDK/header/request dumps; if provenance is not defensible, use fixed prose and record the concrete unsupported diagnostic boundary. Actual credential markers injected into transport fields must not escape; ordinary metadata/content marker tests must prove no broad censor.

Provider non-2xx status is preserved rather than bucketed, using categories: 400/422→invalid_request_error; 429→rate_limit_exceeded; other 4xx including 401/403/404/408/409/424→failed_dependency; 5xx→internal_server_error. Native type is retained in bounded param rather than replacing the registered category; provider model-not-found is not a public route lookup failure. Unknown route still uses fixed model_not_found. For status-zero transport failures keep existing safe timeout/upstream classifications; successful-HTTP stream errors retain valid reported status (including 200) and reviewed native details with existing stream fields.

HTTP retry is pinned status-based: 408/409/429/5xx retry, other 4xx do not. The pinned public client does not honor provider `IsRetryable` overrides on non-2xx status by a new body flag. Record/test any disagreement (e.g. nonretryable provider 500) rather than claiming preservation or changing the dialect. In SSE, existing `statusCode`/`retryable` preserve the provider's reviewed retry flag on an error part; pinned TS forwards plain error values, not a newly constructed GatewayError. Go maps them independently. A provider error part remains ordered/non-terminal at the provider boundary; this does not alter core's separate termination policy.

Post-provider adaptation failure (unsupported/invalid output, bound/encoding failure) remains a safe internal precommit failure or fixed terminal SSE frame postcommit. Existing HTTP 500 is retryable in pinned clients; high-level retry may pay twice. Do not change that incidentally, assert call counts under chosen caller retry settings and explicitly state no exactly-once guarantee. Accepted valid reasoning/metadata/source output must not accidentally trigger such retryable adaptation errors. No client/fallback replay after commitment/output, and no synthetic finish/block closure.

### 5. Debugging, security and telemetry are distinct surfaces

Supported debugging is local Gateway request body plus bounded Gateway HTTP response body/headers in the clients, actual registered response identity (with unary caveat above), and reviewed bounded provider errors. Native URLs/headers/request or response bodies are not promised even on customer-owned keys: they may include account credentials, signed URLs, endpoint routing and SDK dumps, and TS overwrites native request/response anyway. Do not tunnel them through providerMetadata or invent a debug endpoint/field. Outer authentication is never inserted in client-generated request metadata. Preserve the existing reviewed Gateway response-header boundary; do not restore native headers via it.

Metadata and content are provider response data, not arbitrary secret candidates. Credential removal operates on known credential-bearing sources/owned transport fields, not an application-string classifier. Protect other-tenant state by scoped authorization and no catalog/config introspection beyond visible routes. Tests with two authenticated fixture contexts and distinct private markers demonstrate no cross-context response/state exposure; they do not claim a deployed per-customer credential store exists.

Keep `gateway-text-observability` unchanged: canonical logical identity, closed outcomes/counts, no caller text, warnings prose, sources, metadata, provider errors or native identities in logs/labels/metadata-only AO, including internal teams. Test outputs and telemetry separately with unique markers so preserving a caller field is not mistaken for a leak into telemetry.

## Risks / Trade-offs

- [Typed unary identity is overwritten upstream] → test raw body access and document the support boundary; no new dialect or silent parity claim.
- [TS code/details and retry override limitations] → test cause/body and actual class behavior; record nonrepresentable semantics for coordinated future work.
- [Provider error fields may echo credentials] → adapter provenance plus fixed auth prose, no generic error transport or secret-looking-string heuristics.
- [Message-only SSE/local errors lack structured provenance] → fixed safe fallback and tracked producer gap; never assume #299 has already landed.
- [Source IDs and error shapes break normalization-dependent callers] → client-first compatible decoding, explicit release notes, tests of old-server/new-client and new-server/new-client; no compatibility mode.
- [Metadata widens parsing/encoding cost] → #280-owned budgets, original-input preflight and complete serialized limits, independently tested hostile clients.
- [Retryable adaptation or interrupted HTTP 200 can duplicate generation] → retain pinned behavior, demonstrate counts, no exactly-once promise or implicit replay.
- [Full authentic two-client replay harness is not delivered: #201 remains an open draft] → preserve #201 ownership, verify deployment before full matrix acceptance and keep focused PRs independently green with current registered checks.
- [Startup accounts cannot prove deployed BYOK isolation] → scope fixture tests accurately; provisioning/activation remain separate (#104).

## Migration Plan

Land focused self-contained behavior PRs, each green against this reference and updating its normative requirements in the same PR. Do not archive this omnibus plan before those implementations satisfy their applicable deltas; split/sync only delivered requirements to avoid specifications claiming unshipped behavior. Existing archive history stays intact. Release independent client/producer modules as required, verify published pins, then deploy candidate-source Gateway image. Rollback server response changes with its image revision, leaving tolerant upgraded client readers compatible with old fixed envelopes; producer/consumer dependency rollbacks use published pins, never server DTO imports. No credential migration or new service configuration is required.
