## MODIFIED Requirements

### Requirement: Public topology confidentiality
Discovery/public resolution and logical observation SHALL retain requested/public canonical route identity and exclude configuration/credentials/endpoints/provider-instance/candidate count/order/operator topology. Caller ProviderWire data SHALL preserve implemented actual response identity/source display/warnings at registered fields, not be made indistinguishable solely to hide the selected provider. Configured backend IDs SHALL not be synthesized as configuration dumps; a supplied actual response model value remains caller semantics. Typed unary identity stays raw-body-only under the pinned overwrite.

Ambiguous/exhausted fallback errors SHALL retain fixed-safe projection in the minimal foundation without aggregate prose/candidate enumeration or pairing one branch's diagnostic policy with another's error. Fuller actionable aggregate diagnostics requiring representation/transport work SHALL be an explicit separately registered Gateway handoff coordinated with #299, not new stream/error-tree machinery here. Logical telemetry SHALL exclude caller/actual identity/error/metadata fields.

#### Scenario: Candidate identities differ
- **WHEN** selected candidates supply different registered actual model identities
- **THEN** caller values SHALL survive while discovery/logical telemetry remains canonical and configuration/topology stays excluded

#### Scenario: Fallback is exhausted
- **WHEN** joined failures lack trusted unambiguous diagnostic pairing within existing paths
- **THEN** fixed-safe projection SHALL remain without aggregate prose or invasive foundation error machinery
- **AND** the diagnostic gap SHALL be recorded as later work, not justified by a shared-account secret assumption

### Requirement: Empty message options retain text fallback eligibility
Supported semantically empty ordinary namespaces SHALL retain fallback eligibility/value preservation. Active null/false/zero/string/array/object members SHALL not be recursively reclassified empty. Namespaces actually ignored by every candidate MAY be removed; active options consumed by a candidate but lacking safe common routing SHALL be explicitly refused before invocation, not silently stripped by a zero/intersection policy. Invalid/reserved/credential/effectful/file/tool controls retain existing refusal precedence.

#### Scenario: Consumed option would be silently lost
- **WHEN** candidate policy intersection removes an active option consumed by a candidate
- **THEN** no candidate SHALL execute and an explicit nonretryable unsupported-request error SHALL replace silently altered success

#### Scenario: Empty namespace is harmless
- **WHEN** a permitted text request carries only a supported empty message namespace
- **THEN** existing eligibility and unchanged value forwarding SHALL remain

### Requirement: Immutable direct-Anthropic construction
The service SHALL retain once-at-startup hardened explicit provider/candidate/catalog construction, ambient-default exclusion, immutable canonical/alias resolution, ordered fallback and one private attempt hook. Logical identity remains canonical, but actual supplied unary/stream response identity SHALL follow the registered caller policy instead of substitution/omission. Unary native identity is available only in raw response body after pinned typed overwrite; native transport remains excluded.

Trusted direct-route diagnostic policy MAY be attached during existing construction/resolution for minimal projection through existing handler paths; unreviewed/fallback routes SHALL be fixed-safe. No new stream-lifecycle/error wrapper or public error API redesign SHALL be required.

#### Scenario: Alias resolves repeatedly
- **WHEN** canonical and alias IDs resolve
- **THEN** immutable composed model/canonical identity SHALL remain while supplied response identity is not overwritten

### Requirement: Authenticated direct-Anthropic text execution
Current strict supported text execution/authentication/mapping/scalar forwarding/bounds/lifecycle SHALL remain through direct or ordered fallback routes. The foundation SHALL preserve warnings/source display/actual identity without requiring future metadata transport. Minimal trusted direct-provider diagnostics follow existing paths; ambiguous fallback errors remain safe with explicit handoff. Any first part including error/source commits; no changed retry/ordering/replay/core termination/finish authority is introduced.

#### Scenario: Direct or fallback succeeds
- **WHEN** an authorized supported text request succeeds through a selected candidate
- **THEN** current lifecycle and implemented caller fields SHALL survive without publishing topology or claiming future metadata acceptance

#### Scenario: First provider error commits
- **WHEN** a candidate emits PartError as its first part
- **THEN** existing commitment/non-terminal provider ordering SHALL remain and no later candidate SHALL execute
