# Core deferred-tool discovery

These provider-independent fixtures are generated by
`pnpm --dir test/conformance/tools exec tsx deferred-tool-discovery.mts` using
registered `ai@7.0.109`, provider-utils 5.0.45 and provider 4.0.17. The reference
source is vercel/ai commit `4e8c387622ee1bb0d55841664416d38754d5c9a3`,
`packages/ai/src/tool-search/tool-search.test.ts` (direct early-call and nested
caller lifecycle cases) and `prepare-tool-search.test.ts`.

`scenario.json` is synthetic core mock input, not a provider recording.
`expected.jsonl` is the pinned upstream UI stream; `expected-requests.jsonl`
captures full core tool definitions, prompts and tool choice before each model
step. Go replays real ToolSearch and deferred entries against the same model
calls, rather than injecting precomputed search results. The direct case rejects
a premature call and executes it only on the next step; nested search keeps the
caller definition stable and announces the discovered catalog next step.

The message ID is fixed. Tool definitions and caller catalog names are sorted
for the documented Go map-order adaptation; these cases have no tied scores.
No error text, chunk fields, schemas or prompt content are normalized away.
These fixtures establish core orchestration and UI behavior, not live provider
acceptance or provider-hosted tool search.
