# Effective tool choice UI fixtures

Synthetic, provider-independent core scenarios adapted from the registered
`ai@7.0.109` source at `4e8c387622ee1bb0d55841664416d38754d5c9a3`:

- `required-no-call`: `packages/ai/src/generate-text/stream-text.test.ts`,
  “should surface an error when a required tool choice produces no tool call”.
- `named-miss`: the same file, “should surface an error when a different tool is
  called instead of the required tool”.

Inputs retain those reasoning/text/call shapes with a stream-start event,
explicit usage and opaque finish metadata. They are not captured provider
responses or imported provider fixtures. Expectations are generated by the
installed pinned `ai` runtime; message IDs and error text are normalized in both
runtimes. These snapshots establish UI ordering and terminal finish semantics,
not local approval timing (Go batches approvals after model streaming).

From `test/conformance/tools`, regenerate with:

```sh
pnpm exec tsx ../ui/effective-tool-choice/required-no-call/generate.mts
pnpm exec tsx ../ui/effective-tool-choice/named-miss/generate.mts
```
